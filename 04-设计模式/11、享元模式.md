# 1、场景引入

象棋游戏有 32 个棋子对象，大量对局时若每盘棋都 new 32 个完整棋子对象，内存压力大。实际上「黑车」「白马」等同类型棋子，**内在状态（规则、外观）可共享**，只有「在棋盘上的位置」不同。

# 2、普通写法

```java
public class ChessPiece {
    String color;   // 黑/白
    String type;    // 车/马/...
    int row, col;   // 位置

    public ChessPiece(String color, String type, int row, int col) {
        this.color = color;
        this.type = type;
        this.row = row;
        this.col = col;
    }
}
// 32 个棋子 × N 盘棋 = 大量重复 color+type 数据
```

**问题**：Intrinsic 状态（不变）被重复存储；对象数量大时内存浪费。

# 3、设计模式做法

## 介绍

享元模式（Flyweight）：运用共享技术有效地支持**大量细粒度对象**的重用。将状态分为：

| 类型 | 说明 | 示例 |
| :--- | :--- | :--- |
| 内部状态（Intrinsic） | 可共享、不变 | 棋子颜色、类型 |
| 外部状态（Extrinsic） | 随环境变化、由客户端传入 | 棋盘坐标 |

```java
// 享元：内部状态（颜色+类型）可共享
public class PieceFlyweight {
    private final String color;
    private final String type;

    public PieceFlyweight(String color, String type) {
        this.color = color;
        this.type = type;
    }

    // 外部状态（坐标）由调用方传入
    public void display(int row, int col) {
        System.out.println(color + type + " @ " + row + "," + col);
    }
}

// 享元工厂：池化复用
public class PieceFactory {
    private static final Map<String, PieceFlyweight> POOL = new HashMap<>();

    public static PieceFlyweight get(String color, String type) {
        String key = color + type;
        return POOL.computeIfAbsent(key, k -> new PieceFlyweight(color, type));
    }
}
```

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        // 内部状态从工厂池取（共享），位置作为外部状态传入
        PieceFlyweight blackRook = PieceFactory.get("黑", "车");
        blackRook.display(0, 0);
        blackRook.display(0, 7); // 同一享元，不同坐标
    }
}
```

## 注意事项

1. 适合对象数量极大、且大量状态可共享（String 常量池、连接池元数据）。
2. 需要维护享元池，增加系统复杂度。
3. 外部状态不能放在享元内部，否则无法共享。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| `Integer.valueOf(-128~127)` | 小整数缓存池 |
| `String` 常量池 | 相同字面量共享 |
| 数据库连接池 | 连接对象复用 |
| ThreadLocal + 共享不可变对象 | 线程间共享元数据、隔离外部状态 |
