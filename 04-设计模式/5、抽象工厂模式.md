# 1、场景引入

UI 库要支持多套主题：**Windows 风格**和 **Mac 风格**。每套都包含配套的 Button、TextField、Checkbox。客户端只选「Windows 主题」或「Mac 主题」，就能拿到**风格一致的一整套控件**，不能 Windows 按钮配 Mac 输入框。

# 2、普通写法

```java
public class Client {
    public void createUI(String theme) {
        if ("win".equals(theme)) {
            new WinButton();
            new WinTextField();
        } else if ("mac".equals(theme)) {
            new MacButton();
            new MacTextField();
        }
    }
}
```

**问题**：每增加一个控件类型或一套主题，客户端 if-else 暴涨；容易混用不同风格的控件；创建逻辑分散。

# 3、设计模式做法

## 介绍

抽象工厂模式（Abstract Factory）：提供一个接口，用于创建**相关或依赖对象的家族**，而不指定具体类。

## 角色

| 角色 | 说明 |
| :--- | :--- |
| AbstractProduct | 各产品抽象（Button、TextField） |
| ConcreteProduct | 具体产品（WinButton、MacButton） |
| AbstractFactory | 抽象工厂，声明创建一族产品的方法 |
| ConcreteFactory | 具体工厂（WinFactory、MacFactory） |

```java
// 抽象产品
public interface Button { void render(); }
public interface TextField { void render(); }

// 具体产品：Windows 按钮
public class WinButton implements Button {
    public void render() { System.out.println("Win Button"); }
}

public class MacButton implements Button {
    public void render() { System.out.println("Mac Button"); }
}

// 抽象工厂：创建一族配套产品
public interface UIFactory {
    Button createButton();
    TextField createTextField();
}

// 具体工厂：Windows 主题整套
public class WinFactory implements UIFactory {
    public Button createButton() { return new WinButton(); }
    public TextField createTextField() { return new WinTextField(); }
}

public class MacFactory implements UIFactory {
    public Button createButton() { return new MacButton(); }
    public TextField createTextField() { return new MacTextField(); }
}
```

客户端只依赖 `UIFactory`，切换主题 = 换工厂实现。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        // 切换主题 = 换工厂，产品族风格一致
        UIFactory factory = new WinFactory(); // 或 new MacFactory()
        Button btn = factory.createButton();
        TextField field = factory.createTextField();
        btn.render();
        field.render();
    }
}
```

## 与工厂方法的区别

| | 工厂方法 | 抽象工厂 |
| :--- | :--- | :--- |
| 创建范围 | 一种产品 | **一族**产品 |
| 扩展 | 加产品 + 加工厂子类 | 加产品需改抽象工厂接口（扩展性弱） |
| 典型场景 | 一种对象的多种实现 | 多产品组合成套（主题、数据库族） |

## 注意事项

1. 保证产品族内风格一致。
2. 新增**产品等级**（如加 Slider）要改 AbstractFactory 及所有实现，扩展性不如工厂方法灵活。
3. 常与建造者区分：抽象工厂关注「成套产品」；建造者关注「一个复杂对象的分步组装」。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| `Connection` + `Statement` | JDBC：`DriverManager` 按数据库类型提供配套连接族 |
| Spring `BeanFactory` / `ApplicationContext` | 不同上下文实现提供一整套 Bean 创建能力 |
| `Slf4j` + 具体实现 | 日志 API 与 Logback/Log4j 实现配套 |
| MyBatis `SqlSessionFactory` | 创建 SqlSession、Mapper 等配套对象 |
