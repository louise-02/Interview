# 1、场景引入

披萨店要卖多种披萨（希腊、奶酪等），每种都要经历 prepare → bake → cut → box。业务会不断新增口味，希望**新增品种时少改旧代码**。

# 2、普通写法

## 2.1、在客户端直接 new

```java
public class OrderPizza {
    public Pizza order(String type) {
        Pizza pizza = null;
        if ("greek".equals(type)) {
            pizza = new GreekPizza();
        } else if ("cheese".equals(type)) {
            pizza = new CheesePizza();
        }
        pizza.prepare();
        pizza.bake();
        pizza.cut();
        pizza.box();
        return pizza;
    }
}
```

**问题**：每增加一种披萨都要改 `if-else`；创建逻辑和使用逻辑耦合；违反开闭原则。

## 2.2、简单工厂（常用，但不在 GoF 23 内）

把创建逻辑抽到工厂类，客户端只传类型字符串。

```java
// 简单工厂：集中创建，但扩展仍要改 if-else
public class SimplePizzaFactory {
    public Pizza create(String type) {
        if ("greek".equals(type)) return new GreekPizza();
        if ("cheese".equals(type)) return new CheesePizza();
        throw new IllegalArgumentException("unknown type");
    }
}
```

**优点**：客户端与具体类解耦。  
**缺点**：工厂类仍要改 if-else；新增类型仍不够优雅。

# 3、设计模式做法

## 3.1、工厂方法模式（Factory Method，GoF 创建型）

**定义**：定义创建对象的接口，由**子类决定**实例化哪一个类。把实例化延迟到子类。

**角色**

| 角色 | 说明 |
| :--- | :--- |
| Product | 产品抽象（Pizza） |
| ConcreteProduct | 具体产品（GreekPizza） |
| Creator | 工厂抽象，声明工厂方法 |
| ConcreteCreator | 具体工厂，返回具体产品 |

```java
// 产品抽象
public abstract class Pizza {
    public abstract void prepare();
    public void bake() { System.out.println("bake"); }
    public void cut() { System.out.println("cut"); }
    public void box() { System.out.println("box"); }
}

// 创建者抽象：order 是模板方法，createPizza 是工厂方法
public abstract class OrderPizza {
    protected abstract Pizza createPizza(); // 工厂方法，子类决定 new 哪种

    public Pizza order() {
        Pizza pizza = createPizza();
        pizza.prepare();
        pizza.bake();
        pizza.cut();
        pizza.box();
        return pizza;
    }
}

// 具体创建者：生产希腊披萨
public class GreekOrderPizza extends OrderPizza {
    @Override
    protected Pizza createPizza() {
        return new GreekPizza();
    }
}
```

**优点**：新增披萨 = 新增产品类 + 新增工厂子类，**不用改原有工厂**。  
**缺点**：类数量变多。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        // 简单工厂
        SimplePizzaFactory factory = new SimplePizzaFactory();
        Pizza pizza1 = factory.create("greek");

        // 工厂方法：选具体工厂/订购类
        OrderPizza order = new GreekOrderPizza();
        Pizza pizza2 = order.order();
    }
}
```

## 3.2、三种工厂对比

| | 简单工厂 | 工厂方法 | 抽象工厂 |
| :--- | :--- | :--- | :--- |
| GoF 23 | ❌ | ✅ | ✅ |
| 创建什么 | 一种产品多种变体 | 一种产品多种变体 | **一族**相关产品 |
| 扩展方式 | 改工厂 if-else | 新增工厂子类 | 新增工厂实现族 |

## 注意事项

- 业务里说的「工厂模式」面试语境下通常指 **工厂方法**；简单工厂是常用写法但不算 GoF 23。
- 产品种类少、变化不频繁时，简单工厂够用；扩展频繁时用工厂方法。
- 与抽象工厂区别：工厂方法创建**一种**产品的不同实现；抽象工厂创建**多个产品组成的一套**（见 `5、抽象工厂模式.md`）。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| `Calendar.getInstance()` | 根据 Locale/TimeZone 返回不同 Calendar 实现 |
| `Collection.iterator()` | 各集合子类实现自己的 Iterator 工厂方法 |
| `Spring BeanFactory` | `getBean()` 获取对象，具体创建由容器/FactoryBean 完成 |
| `LoggerFactory.getLogger()` | 按名称创建 Logger 实例 |
| MyBatis `SqlSessionFactory.openSession()` | 工厂创建 SqlSession |
