# 1、场景引入

咖啡店卖咖啡，可以选配：**大杯/中杯**、**加牛奶**、**加摩卡**、**加 whipped cream**。如果用子类 `MochaLargeCoffee`、`MilkSmallCoffee`… 子类数量随配料组合指数增长。

# 2、普通写法

```java
public class Coffee {
    String desc = "Coffee";
    double cost = 5;
    public String getDesc() { return desc; }
    public double cost() { return cost; }
}

public class MilkCoffee extends Coffee {
    public MilkCoffee() {
        desc = "Coffee, Milk";
        cost = 6;
    }
}
// 每多一种配料组合就要一个新子类
```

**问题**：静态继承无法运行时动态组合；类爆炸；难以任意叠加装饰。

# 3、设计模式做法

## 介绍

装饰模式（Decorator）：动态地给对象**附加职责**，比继承更灵活。装饰器与被装饰对象实现同一接口，并在内部持有被装饰对象。

```java
// 组件接口
public abstract class Beverage {
    String desc = "Unknown";
    public String getDesc() { return desc; }
    public abstract double cost();
}

// 具体组件：浓缩咖啡
public class Espresso extends Beverage {
    public Espresso() { desc = "Espresso"; }
    public double cost() { return 5; }
}

// 装饰器抽象：与被装饰对象同接口
public abstract class CondimentDecorator extends Beverage {
    protected Beverage beverage; // 持有被装饰对象
}

// 具体装饰：加牛奶
public class Milk extends CondimentDecorator {
    public Milk(Beverage beverage) {
        this.beverage = beverage;
    }
    public String getDesc() { return beverage.getDesc() + ", Milk"; }
    public double cost() { return beverage.cost() + 1; }
}

// 层层包装：摩卡( 牛奶( 浓缩 ) )
Beverage drink = new Mocha(new Milk(new Espresso()));
```

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        // 运行时任意组合配料，接口始终是 Beverage
        Beverage drink = new Mocha(new Milk(new Espresso()));
        System.out.println(drink.getDesc() + " $" + drink.cost());
    }
}
```

## 与代理区别

| | 装饰 | 代理 |
| :--- | :--- | :--- |
| 目的 | 增强功能，可多层叠加 | 控制访问、延迟加载、权限 |
| 关注点 | 附加职责 | 对象本身可能不变 |

## 注意事项

1. 适合功能可任意组合、需运行时动态扩展。
2. 会产生较多小类，但比子类爆炸可控。
3. 与适配器：装饰接口不变；适配器改接口。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| Java IO 流 | `BufferedInputStream(new FileInputStream(...))` 层层包装 |
| `Collections.synchronizedList()` | 给 List 加同步装饰 |
| Spring `BeanWrapper` | 对 Bean 做属性访问包装 |
| MyBatis `Cache` 装饰链 | 多级缓存装饰 |
