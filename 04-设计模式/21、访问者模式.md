# 1、场景引入

医院里有**病人**、**医生**、**药房**、**账单**等对象。要对它们做「计算费用」「打印报告」等操作。若在每个类里加方法，类会膨胀；若把逻辑全写在外部，又要大量 `instanceof`。

# 2、普通写法

```java
public void calcFee(Object obj) {
    if (obj instanceof Patient) {
        // ...
    } else if (obj instanceof Doctor) {
        // ...
    }
}
```

**问题**：新增元素类型或新增操作都要改多处；违反开闭原则。

# 3、设计模式做法

## 介绍

访问者模式（Visitor）：表示一个作用于某对象结构中各元素的操作。它使你可以在不改变各元素类的前提下**定义作用于这些元素的新操作**。

**关键**：元素类提供 `accept(Visitor v)`，Visitor 为每种具体元素提供 `visit(XxxElement e)`。

```java
// 访问者：一种操作，对每种元素一个 visit 方法
public interface Visitor {
    void visit(Patient patient);
    void visit(Doctor doctor);
}

// 元素：接受访问者（双分派入口）
public interface Element {
    void accept(Visitor visitor);
}

public class Patient implements Element {
    public void accept(Visitor visitor) {
        visitor.visit(this);
    }
}

public class Doctor implements Element {
    public void accept(Visitor visitor) {
        visitor.visit(this);
    }
}

// 具体访问者：计费
public class BillVisitor implements Visitor {
    public void visit(Patient p) { System.out.println("patient fee"); }
    public void visit(Doctor d) { System.out.println("doctor fee"); }
}
```

## 双分派

1. 客户端调用 `element.accept(visitor)`  
2. 元素回调 `visitor.visit(this)`，确定具体类型

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        List<Element> elements = List.of(new Patient(), new Doctor());
        Visitor billVisitor = new BillVisitor();

        for (Element e : elements) {
            e.accept(billVisitor); // 双分派：元素 + 访问者
        }
    }
}
```

## 注意事项

1. 适合**数据结构稳定、操作经常增加**（编译器 AST、报表导出）。
2. 新增元素类型要改 Visitor 及所有实现，扩展元素困难。
3. 使用频率在 23 种里偏低，但编译器、ORM 元数据处理常见。
