# 1、场景引入

遥控器要控制多种电器：电视、收音机。每种设备有「开/关/调音量」等操作，但实现不同。如果为「含音量控制的遥控器」「仅开关的遥控器」各写一套继承树，类会爆炸：**抽象维度 × 实现维度** 用继承会组合失控。

# 2、普通写法

```java
public abstract class RemoteControl {
    public abstract void on();
    public abstract void off();
}

public abstract class RemoteWithVolume extends RemoteControl {
    public abstract void volumeUp();
    public abstract void volumeDown();
}

public class TvRemoteWithVolume extends RemoteWithVolume { /* ... */ }
public class RadioRemoteWithVolume extends RemoteWithVolume { /* ... */ }
// 每增加一种设备或一种遥控能力，子类数量倍增
```

**问题**：抽象（遥控能力）与实现（具体设备）绑死在继承里，两个维度独立变化时子类爆炸。

# 3、设计模式做法

## 介绍

桥接模式（Bridge）：将**抽象部分**与**实现部分**分离，使它们可以独立变化。用组合代替多层继承。

## 角色

| 角色 | 说明 |
| :--- | :--- |
| Abstraction | 抽象（RemoteControl） |
| RefinedAbstraction | 扩展抽象（AdvancedRemote） |
| Implementor | 实现接口（Device） |
| ConcreteImplementor | 具体实现（Tv、Radio） |

```java
// 实现者接口：设备能力
public interface Device {
    void turnOn();
    void turnOff();
    void setVolume(int percent);
}

// 具体实现者：电视
public class Tv implements Device {
    public void turnOn() { System.out.println("TV on"); }
    public void turnOff() { System.out.println("TV off"); }
    public void setVolume(int percent) { System.out.println("TV volume " + percent); }
}

// 抽象：遥控器，组合 Device 而非继承设备
public abstract class RemoteControl {
    protected Device device;

    protected RemoteControl(Device device) {
        this.device = device;
    }

    public void togglePower() {
        device.turnOn();
    }
}

//  refined 抽象：带音量控制的遥控
public class AdvancedRemote extends RemoteControl {
    public AdvancedRemote(Device device) {
        super(device);
    }

    public void volumeUp() {
        device.setVolume(100);
    }
}
```

换设备 = 换 `Device` 实现；换遥控能力 = 换 `RemoteControl` 子类。两维独立扩展。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        Device tv = new Tv();
        RemoteControl remote = new AdvancedRemote(tv);
        remote.togglePower();
        ((AdvancedRemote) remote).volumeUp();
        // 换设备：new AdvancedRemote(new Radio())，Remote 代码不用改
    }
}
```

## 与适配器区别

桥接是**设计阶段**把抽象与实现拆开；适配器是**事后**让不兼容接口能一起工作。

## 注意事项

1. 适合两个（或多个）独立变化维度。
2. 隐藏实现细节，对客户端只暴露抽象接口。
3. JDBC 中 `Driver` 与 `Connection` 也是桥接思想的体现。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| JDBC `Driver` / `Connection` | Java 抽象 API 桥接到各数据库驱动实现 |
| SLF4J + Logback | 日志门面（抽象）与具体实现分离 |
| Spring JDBC `JdbcTemplate` | 模板操作与底层 DataSource 实现分离 |
