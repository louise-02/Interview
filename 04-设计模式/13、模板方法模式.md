# 1、场景引入

制作多种饮料（豆浆、米浆）流程相同：**选豆 → 浸泡 → 打浆 → 煮浆 → 加配料**。每种饮料各步骤细节不同，但**流程顺序不能乱**。

# 2、普通写法

```java
public class SoyMilk {
    public void make() {
        select();
        soak();
        beat();
        boil();
        addCondiments();
    }
    void select() { System.out.println("选黄豆"); }
    // 每个步骤在各子类重复写 make() 流程...
}
```

**问题**：流程代码在每个子类重复；若流程变更要改多处；容易某子类漏步骤。

# 3、设计模式做法

## 介绍

模板方法模式（Template Method）：在抽象类中定义算法**骨架**（final 模板方法），将某些步骤延迟到子类实现。

```java
public abstract class SoyaMilkTemplate {
    // 模板方法：流程固定，子类不能改顺序
    public final void make() {
        select();
        if (needSoak()) soak();       // 钩子：子类可决定是否浸泡
        beat();
        boil();
        addCondiments();              // 抽象步骤：子类实现
    }

    void select() { System.out.println("选豆"); }
    abstract void addCondiments();
    protected boolean needSoak() { return true; }
    void soak() { System.out.println("浸泡"); }
    void beat() { System.out.println("打浆"); }
    void boil() { System.out.println("煮浆"); }
}

// 具体类：只实现变化步骤
public class RedBeanSoyaMilk extends SoyaMilkTemplate {
    @Override
    void addCondiments() {
        System.out.println("加红豆");
    }
}
```

## 钩子方法（Hook）

子类可覆盖 `needSoak()` 等带默认实现的方法，**不改变算法骨架**地改变行为。

## 与策略区别

| | 模板方法 | 策略 |
| :--- | :--- | :--- |
| 关系 | 继承，流程固定 | 组合，算法整体可换 |
| 变化点 | 部分步骤 | 整个策略对象 |

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        RedBeanSoyaMilk milk = new RedBeanSoyaMilk();
        milk.make(); // 调用模板方法，流程固定，细节由子类决定
    }
}
```

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| Spring `JdbcTemplate` | `execute()` 固定获取连接/释放，具体 SQL 由回调实现 |
| `HttpServlet.service()` | 固定请求分发，子类实现 doGet/doPost |
| MyBatis `BaseExecutor` | 执行流程模板，细节子类实现 |
| `AbstractList#iterator()` | 骨架 + 子类实现具体迭代逻辑 |
