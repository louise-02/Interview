# 1、场景引入

聊天室里有多个用户，任意两人发消息若**两两直连**，连接数爆炸且逻辑混乱。希望有一个**中介**统一转发消息，用户只和中介交互。

# 2、普通写法

```java
public class UserA {
    public void send(UserB b, String msg) {
        b.receive(msg);
    }
}
// N 个用户之间 N*(N-1) 种引用关系
```

**问题**：对象网状耦合；新增用户要改多个类；难以集中控制（禁言、审计）。

# 3、设计模式做法

## 介绍

中介者模式（Mediator）：用一个中介对象封装一系列对象交互，使各对象不需要显式相互引用，降低耦合。

```java
// 中介者抽象
public abstract class Mediator {
    public abstract void send(String from, String to, String msg);
}

// 具体中介：聊天室
public class ChatRoom extends Mediator {
    private final Map<String, User> users = new HashMap<>();

    public void register(User user) {
        users.put(user.getName(), user);
    }

    @Override
    public void send(String from, String to, String msg) {
        User target = users.get(to);
        if (target != null) {
            target.receive(from, msg);
        }
    }
}

// 同事类：只和中介通信，不直接引用其他 User
public class User {
    private final Mediator mediator;
    private final String name;

    public User(Mediator m, String name) {
        this.mediator = m;
        this.name = name;
    }

    public void send(String to, String msg) {
        mediator.send(name, to, msg);
    }

    public void receive(String from, String msg) {
        System.out.println(name + " 收到 " + from + ": " + msg);
    }
}
```

## 与外观区别

| | 中介者 | 外观 |
| :--- | :--- | :--- |
| 交互 | 多对象经中介**互相**通信 | 客户端经门面**单向**调子系统 |
| 目的 | 解耦对象间网状依赖 | 简化子系统入口 |

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        ChatRoom room = new ChatRoom();
        User tom = new User(room, "tom");
        User jerry = new User(room, "jerry");
        room.register(tom);
        room.register(jerry);

        tom.send("jerry", "hello"); // 经中介转发，两用户不直接引用
    }
}
```
