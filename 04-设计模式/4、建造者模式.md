# 1、场景引入

盖房流程固定：打桩 → 砌墙 → 封顶。但有普通房、高楼、别墅，各步骤细节不同。希望**建造流程统一**，**不同房型部件可替换**，且最终得到独立的 `House` 对象。

# 2、普通写法

```java
public abstract class AbstractHouse {
    public abstract void buildBasic();
    public abstract void buildWalls();
    public abstract void roofed();

    public void build() {
        buildBasic();
        buildWalls();
        roofed();
    }
}

public class CommonHouse extends AbstractHouse {
    @Override
    public void buildBasic() { System.out.println("普通地基"); }
    @Override
    public void buildWalls() { System.out.println("普通墙"); }
    @Override
    public void roofed() { System.out.println("普通顶"); }
}
```

**问题**：上面其实是**模板方法**——子类既是「房子」又是「建造者」，产品与建造过程绑在一起。  
建造者模式要把 **Product（House）** 与 **Builder（建造步骤）** 分离。

# 3、设计模式做法

## 介绍

建造者模式（Builder）：将复杂对象的**构建过程**与**表示**分离，使同一构建流程可以创建不同表现的产品。

## 四种角色

| 角色 | 说明 |
| :--- | :--- |
| Product | 产品（House） |
| Builder | 抽象建造者，定义各部件建造接口 |
| ConcreteBuilder | 具体建造者，实现各部件 |
| Director | 指挥者，按固定顺序调用 Builder（**可选**） |

## 代码实现

```java
// 产品：最终建造出来的对象
@Data
public class House {
    String basic;
    String walls;
    String roofed;
}

// 抽象建造者
public abstract class HouseBuilder {
    protected House house = new House(); // 每个 builder 持有一份产品

    public abstract void buildBasic();
    public abstract void buildWalls();
    public abstract void roofed();

    public House getHouse() {
        return house;
    }
}

// 具体建造者：普通房
public class CommonHouseBuilder extends HouseBuilder {
    @Override
    public void buildBasic() { house.setBasic("普通地基"); }
    @Override
    public void buildWalls() { house.setWalls("普通墙"); }
    @Override
    public void roofed() { house.setRoofed("普通顶"); }
}

// 指挥者：固定建造顺序（可选）
public class HouseDirector {
    private final HouseBuilder builder;

    public HouseDirector(HouseBuilder builder) {
        this.builder = builder;
    }

    public House createHouse() {
        builder.buildBasic();
        builder.buildWalls();
        builder.roofed();
        return builder.getHouse();
    }
}
```

## 链式 Builder（无 Director，更常见）

```java
House house = new CommonHouseBuilder()
    .buildBasic()
    .buildWalls()
    .roofed()
    .getHouse();
// 或 Lombok @Builder
```

## 注意事项

1. 客户端不必知道产品内部组成，构建与表示解耦。
2. 替换 ConcreteBuilder 即可得到不同产品，符合开闭原则。
3. 产品部件相似、步骤固定时最合适；产品差异极大时不适合。
4. **抽象工厂**管「产品族」；**建造者**管「按步骤组装一个复杂对象」。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        // 方式1：Director 固定流程
        HouseDirector director = new HouseDirector(new CommonHouseBuilder());
        House house = director.createHouse();

        // 方式2：客户端自行链式调用（无 Director）
        // House house = new CommonHouseBuilder().buildBasic()...getHouse();
    }
}
```

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| `StringBuilder` / `StringBuffer` | 链式 `append()` 逐步构建字符串；通常**无 Director**，客户端自行调用 |
| Lombok `@Builder` | 编译期生成 Builder，业务 DTO/Entity 常用 |
| `OkHttp Request.Builder` | 分步设置 URL、Header、Body 后 `build()` |
| `Spring Security OAuth2Client` 等 | 复杂配置对象的分步构建 |
