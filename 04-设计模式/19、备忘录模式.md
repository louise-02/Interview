# 1、场景引入

文本编辑器需要**撤销/重做**：用户改内容后，能恢复到之前某个版本。不能把整个 Editor 对象序列化备份（太大），只想保存**必要的状态快照**。

# 2、普通写法

```java
public class Editor {
    String content;
    String history; // 简单字符串备份，难以多步撤销
}
```

**问题**：备份粒度难控制；恢复逻辑与编辑器耦合；多步历史难管理。

# 3、设计模式做法

## 介绍

备忘录模式（Memento）：在不破坏封装的前提下，捕获对象的内部状态，并在之后恢复该状态。

```java
// 备忘录：保存某一时刻的状态快照
public class EditorMemento {
    private final String content;

    public EditorMemento(String content) {
        this.content = content;
    }

    String getContent() {
        return content;
    }
}

// 原发器：知道如何保存/恢复自身状态
public class Editor {
    private String content;

    public void setContent(String content) {
        this.content = content;
    }

    public EditorMemento save() {
        return new EditorMemento(content);
    }

    public void restore(EditorMemento memento) {
        this.content = memento.getContent();
    }
}

// caretaker：只存备忘录，不碰 Editor 内部
public class History {
    private final Stack<EditorMemento> stack = new Stack<>();

    public void push(EditorMemento m) { stack.push(m); }
    public EditorMemento pop() { return stack.pop(); }
}
```

**Caretaker（历史栈）** 只存 Memento，不应依赖 Editor 内部细节。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        Editor editor = new Editor();
        History history = new History();

        editor.setContent("v1");
        history.push(editor.save());

        editor.setContent("v2");
        editor.restore(history.pop()); // 恢复到 v1
    }
}
```

## 注意事项

1. Memento 可以是深拷贝快照，避免共享引用被改。
2. 状态很大时内存占用高，可限制栈深度。
3. 与原型：原型是复制对象造新实例；备忘录是保存状态以便**恢复同一对象**。
