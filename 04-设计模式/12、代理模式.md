# 1、场景引入

有一个 `UserService`，想在调用前后加：**权限校验**、**事务**、**日志**、**缓存**。不想改 `UserService` 源码，也不能用继承把每种组合都写一遍。

# 2、普通写法

```java
public class UserService {
    public void saveUser(User user) {
        System.out.println("check auth");
        System.out.println("begin tx");
        System.out.println("save user");
        System.out.println("commit tx");
    }
}
```

**问题**：横切逻辑与业务耦合；多种增强组合难以复用；违反单一职责。

# 3、设计模式做法

## 介绍

代理模式（Proxy）：为其他对象提供一种**代理**以控制对这个对象的访问。

## 常见类型

| 类型 | 说明 |
| :--- | :--- |
| 静态代理 | 手写代理类，实现与目标相同接口 |
| JDK 动态代理 | 基于接口，反射生成代理 |
| CGLIB 动态代理 | 基于子类，可代理无接口类 |

**静态代理示意**

```java
// 抽象主题
public interface UserService {
    void saveUser(User user);
}

// 真实对象
public class UserServiceImpl implements UserService {
    public void saveUser(User user) {
        System.out.println("save user");
    }
}

// 代理：与目标同接口，前后可加横切逻辑
public class UserServiceProxy implements UserService {
    private final UserService target; // 持有真实对象

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    public void saveUser(User user) {
        System.out.println("log before");
        target.saveUser(user); // 委托给真实对象
        System.out.println("log after");
    }
}
```

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();
        UserService proxy = new UserServiceProxy(target);
        proxy.saveUser(new User()); // 客户端调接口，不知/不直接调真实对象
    }
}
```

## 与装饰区别

| | 代理 | 装饰 |
| :--- | :--- | :--- |
| 关系 | 常控制访问、延迟创建 | 常增强功能 |
| 对客户端 | 可能不知道真实对象 | 知道是在「包装」 |

## 注意事项

1. Spring AOP、RPC 客户端、MyBatis Mapper 都是代理典型场景。
2. JDK 代理要求目标有接口；CGLIB 通过子类，不能代理 final 类/方法。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| Spring AOP | JDK/CGLIB 动态代理实现切面 |
| MyBatis Mapper 接口 | JDK 动态代理，无实现类 |
| Feign / Dubbo 客户端 | 远程接口本地代理 |
| `java.lang.reflect.Proxy` | JDK 动态代理入口 |
