# 1、场景引入

气象站温度变化后，需要通知：**当前显示屏**、**统计模块**、**预警模块**。以后还可能加新订阅者，且各订阅者更新方式不同。

# 2、普通写法

```java
public class WeatherData {
    private float temperature;

    public void setTemperature(float t) {
        this.temperature = t;
        // 每加一个观察者就要改这里
        display.update(t);
        statistics.update(t);
        alert.update(t);
    }
}
```

**问题**：主题与观察者紧耦合；新增/删除订阅者要改主题代码；违反开闭原则。

# 3、设计模式做法

## 介绍

观察者模式（Observer）：定义对象间**一对多**依赖，当被观察者状态改变时，所有依赖者自动收到通知并更新。

```java
// 观察者
public interface Observer {
    void update(float temperature);
}

// 主题：维护观察者列表，状态变化时通知
public class WeatherData {
    private float temperature;
    private final List<Observer> observers = new ArrayList<>();

    public void register(Observer o) { observers.add(o); }
    public void remove(Observer o) { observers.remove(o); }

    public void setTemperature(float t) {
        this.temperature = t;
        notifyObservers();
    }

    private void notifyObservers() {
        for (Observer o : observers) {
            o.update(temperature);
        }
    }
}
```

JDK 自带 `java.util.Observable` / `Observer`（已 deprecated），思想相同。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        WeatherData data = new WeatherData();
        data.register(t -> System.out.println("display: " + t));
        data.register(new Observer() {
            public void update(float t) {
                System.out.println("stats: " + t);
            }
        });
        data.setTemperature(25.5f);
    }
}
```

## 注意事项

1. 推模式（主题推送全部数据）vs 拉模式（观察者按需拉取）。
2. 注意循环通知、内存泄漏（忘记 remove）。
3. 与发布订阅：观察者常是进程内直接调用；发布订阅常经消息中间件解耦。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| Spring `ApplicationEvent` | 事件发布 + `@EventListener` 订阅 |
| `java.beans.PropertyChangeListener` | 属性变更通知 |
| GUI `ActionListener` | 按钮事件监听 |
| Redis Pub/Sub、MQ | 广义的观察者/发布订阅思想 |
