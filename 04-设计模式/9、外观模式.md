# 1、场景引入

家庭影院开机要依次：开投影仪、开屏幕、开功放、开 DVD、关灯光… 用户不想记这么多步骤，只想按一个「观影」按钮。

# 2、普通写法

```java
public class Client {
    public void watchMovie() {
        Projector projector = new Projector();
        Screen screen = new Screen();
        Amplifier amp = new Amplifier();
        projector.on();
        screen.down();
        amp.on();
        amp.setVolume(5);
        // 客户端与子系统每个类都耦合
    }
}
```

**问题**：客户端依赖多个子系统类；流程复杂；子系统变更影响所有调用方。

# 3、设计模式做法

## 介绍

外观模式（Facade）：为子系统中的一组接口提供一个**统一的高层接口**，使子系统更易使用。

```java
// 外观：封装子系统复杂调用
public class HomeTheaterFacade {
    private final Projector projector;
    private final Screen screen;
    private final Amplifier amp;

    public HomeTheaterFacade(Projector p, Screen s, Amplifier a) {
        this.projector = p;
        this.screen = s;
        this.amp = a;
    }

    public void watchMovie() {
        projector.on();
        screen.down();
        amp.on();
        amp.setVolume(5);
    }

    public void endMovie() {
        projector.off();
        screen.up();
        amp.off();
    }
}
```

客户端只依赖 Facade，不直接碰子系统细节。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        HomeTheaterFacade facade = new HomeTheaterFacade(
            new Projector(), new Screen(), new Amplifier());
        facade.watchMovie(); // 一键完成多步子系统调用
        facade.endMovie();
    }
}
```

## 注意事项

1. 外观**不阻止**客户端直接访问子系统，只是提供便捷入口。
2. 与中介者：外观是**单向**封装调用；中介者处理**多对象之间**的复杂交互。
3. 常用于 Service 层聚合多个 DAO/远程调用，对外一个方法。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| SLF4J | 日志门面，屏蔽 Log4j/Logback 细节 |
| Spring `@Service` 业务门面 | 聚合多个 Mapper/Client，Controller 只调 Service |
| JDBC `Connection` | 对底层驱动复杂 API 的简化使用（与桥接叠加） |
| MyBatis `SqlSession` | 简化 Executor、Mapper 等底层协作 |
