# 1、场景引入

电梯有四种状态：**开门、关门、运行、停止**。在不同状态下按同一按钮行为不同：运行中按开门无效，停止时按开门才有效。若用大量 if-else 判断状态，代码难维护。

# 2、普通写法

```java
public class Elevator {
    int state; // 0开 1关 2运行 3停

    public void open() {
        if (state == RUNNING) {
            // 无效
        } else if (state == STOPPED) {
            state = OPEN;
        }
        // 状态越多 if 越复杂
    }
}
```

**问题**：行为与状态判断混在一起；新增状态要改所有方法。

# 3、设计模式做法

## 介绍

状态模式（State）：允许对象在**内部状态改变时改变它的行为**，对象看起来好像修改了它的类。把每个状态封装成独立类。

```java
// 状态接口：每种状态一种行为
public interface ElevatorState {
    void open(Elevator context);
    void close(Elevator context);
    void run(Elevator context);
}

// 具体状态
public class RunningState implements ElevatorState {
    public void open(Elevator ctx) {
        System.out.println("运行中不能开门");
    }
    public void close(Elevator ctx) { /* ... */ }
    public void run(Elevator ctx) { /* ... */ }
}

// 上下文：持有当前状态，操作委托给 state
public class Elevator {
    private ElevatorState state = new StoppedState();

    public void setState(ElevatorState state) {
        this.state = state;
    }

    public void open() {
        state.open(this); // 同样 open()，不同状态行为不同
    }

    public void close() {
        state.close(this);
    }

    public void run() {
        state.run(this);
    }
}
```

状态转换可在 State 类内部完成（如 `ctx.setState(new OpenState())`）。

## 与策略区别

| | 状态 | 策略 |
| :--- | :--- | :--- |
| 切换 | 状态对象间自动/内部转换 | 通常由客户端显式 set |
| 语义 | 对象「处于某种状态」 | 对象「选用某种算法」 |

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        Elevator elevator = new Elevator();
        elevator.open();  // 行为取决于当前 State 对象
        elevator.run();
        elevator.close();
    }
}
```

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
| TCP 连接状态 | CLOSED、ESTABLISHED 等 |
| 订单状态机 | 待支付→已支付→已发货→完成 |
| Spring State Machine | 工作流/订单状态流转 |
| 线程 `Thread` 状态 | NEW、RUNNABLE、BLOCKED 等 |
