# 1、场景引入

文件系统有**文件**和**文件夹**，文件夹里还可以放文件或子文件夹。希望对「单个文件」和「整个目录树」做统一操作：如显示结构、统计大小、删除。

# 2、普通写法

```java
public class File {
    String name;
    long size;
}

public class Folder {
    String name;
    List<File> files = new ArrayList<>();
    List<Folder> folders = new ArrayList<>();
}

public void print(Folder folder) {
    for (File f : folder.files) { /* 打印文件 */ }
    for (Folder sub : folder.folders) { print(sub); } // 递归，客户端逻辑复杂
}
```

**问题**：客户端要区分 File/Folder 并写递归；新增统一操作（如权限检查）要在多处改。

# 3、设计模式做法

## 介绍

组合模式（Composite）：将对象组合成**树形结构**以表示「部分-整体」层次，使客户端对单个对象和组合对象的使用**保持一致**。

```java
// 组件抽象：叶子和容器统一接口
public abstract class FileSystemNode {
    protected String name;
    public abstract long getSize();
    public abstract void display(int depth);
}

// 叶子节点：文件
public class FileLeaf extends FileSystemNode {
    private long size;

    public FileLeaf(String name, long size) {
        this.name = name;
        this.size = size;
    }

    public long getSize() { return size; }
    public void display(int depth) {
        System.out.println("  ".repeat(depth) + name);
    }
}

// 组合节点：目录，可包含子节点
public class Directory extends FileSystemNode {
    private List<FileSystemNode> children = new ArrayList<>();

    public Directory(String name) {
        this.name = name;
    }

    public void add(FileSystemNode node) { children.add(node); }

    public long getSize() {
        return children.stream().mapToLong(FileSystemNode::getSize).sum();
    }

    public void display(int depth) {
        System.out.println("  ".repeat(depth) + name + "/");
        children.forEach(c -> c.display(depth + 1));
    }
}
```

客户端只面向 `FileSystemNode`，不用关心是叶子还是容器。

## 客户端调用

```java
public class Client {
    public static void main(String[] args) {
        Directory root = new Directory("root");
        Directory docs = new Directory("docs");
        docs.add(new FileLeaf("readme.txt", 1024));
        root.add(docs);
        root.display(0);              // 文件和目录同一套 display
        System.out.println(root.getSize()); // 递归统计大小
    }
}
```

## 注意事项

1. 适合树形结构：菜单、组织架构、权限树、文件系统。
2. 透明式（子节点操作也放在抽象类）vs 安全式（只有 Directory 能 add）。
3. 与装饰：组合是结构型「整体-部分」；装饰是叠加行为。

# 4、源码中的运用

| 案例 | 说明 |
| :--- | :--- |
