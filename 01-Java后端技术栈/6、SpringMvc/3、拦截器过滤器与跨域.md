# 3、拦截器过滤器与跨域

## 1、Filter vs Interceptor

| | Filter | HandlerInterceptor |
| - | ------ | ------------------ |
| 规范 | Servlet | Spring MVC |
| 作用范围 | 所有 Servlet 请求 | DispatcherServlet 管理的 Handler |
| 顺序 | 更靠前 | Controller 前后 |
| 典型用途 | 编码、XSS、Shiro | 登录鉴权、日志、ThreadLocal 清理 |

```
Filter → DispatcherServlet → Interceptor → Controller
```

## 2、Interceptor 三个方法

- **preHandle**：Controller 前；return false 中断。
- **postHandle**：Controller 后、视图前（JSON 项目少用）。
- **afterCompletion**：请求结束，清 ThreadLocal、记耗时。

注册：`WebMvcConfigurer.addInterceptors`（见 SpringBoot.md）。

## 3、CORS 跨域

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOriginPatterns("*")
                .allowedMethods("*")
                .allowCredentials(true);
    }
}
```

网关统一 CORS 时，后端可关闭重复配置。

## 4、全局异常与 @ControllerAdvice

`@RestControllerAdvice` 集中处理异常，返回统一 JSON（与 SpringBoot 实践文档一致）。

## 5、常见面试题

**1. 拦截器和 Filter 执行顺序？**

Filter 先；Interceptor 在 DispatcherServlet 内、Controller 前后。

**2. 如何做登录校验？**

Interceptor preHandle 查 Token/Session；或 Spring Security Filter 链。

**3. 为什么 afterCompletion 要 remove ThreadLocal？**

线程池复用线程，不清理会数据错乱、内存泄漏。
