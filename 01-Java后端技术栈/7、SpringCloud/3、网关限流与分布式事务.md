# 3、网关限流与分布式事务

## 1、Spring Cloud Gateway

基于 **WebFlux** 的反应式网关（非 Servlet Tomcat 线程模型）。

**核心概念**

- **Route**：ID + URI + Predicate + Filter
- **Predicate**：路径、Header、时间等匹配
- **Filter**：鉴权、StripPrefix、限流、重写 URL

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: order
          uri: lb://order-service
          predicates:
            - Path=/api/order/**
          filters:
            - StripPrefix=1
```

**与 Nginx 分工**：Nginx 边缘 TLS、静态资源；Gateway 统一鉴权、路由、灰度。

## 2、Sentinel

流量控制、熔断降级、系统负载保护。

| 规则 | 说明 |
| ---- | ---- |
| QPS 限流 | 超过阈值快速失败 |
| 并发线程数 | 慢调用保护 |
| 熔断 | 异常比例/慢调用比例达阈值，打开熔断窗口 |

整合 Feign：`fallback` / `fallbackFactory` 返回降级结果。

控制台动态推规则；生产规则持久化到 Nacos。

## 3、Seata 分布式事务

**AT 模式**（常用）：拦截业务 SQL，记录 undo log，二阶段提交/回滚。

```
TM 开启全局事务 @GlobalTransactional
  → RM 分支注册到 TC
  → 一阶段提交本地 + undo
  → 二阶段 TC 通知 commit/rollback
```

**其他模式**：TCC（手写 confirm/cancel）、SAGA（长事务补偿）、XA（强一致，性能低）。

**注意**：跨库、跨服务才需要；能避免则通过**本地消息表 / 最终一致**更简单。

## 4、链路追踪

Sleuth 传递 TraceId/SpanId；Zipkin/SkyWalking 收集；Gateway 入口生成 TraceId 向下游传递。

## 5、常见面试题

**1. Gateway 和 Zuul1 区别？**

Gateway WebFlux 非阻塞；Zuul1 Servlet 阻塞；Zuul2 未广泛替代 Gateway。

**2. 熔断和限流区别？**

限流防流量过大；熔断防依赖故障拖垮自身（失败率/慢调用触发）。

**3. Seata AT 原理？**

一阶段业务 SQL + undo log；二阶段异步删 undo 或回滚；需支持的数据源代理。
