# 3、对象与内存布局

## 1、对象的创建过程

```
new 指令
  → 检查常量池中能否定位到类符号引用，类是否已加载、解析、初始化
  → 在堆上分配内存（指针碰撞 / 空闲列表，取决于是否整理）
  → 零值初始化（除对象头外字段设为 0 / false / null）
  → 设置对象头（Mark Word、类型指针等）
  → 执行 <init> 方法（构造器）
```

**内存分配方式**

| 方式 | 条件 | 说明 |
| ---- | ---- | ---- |
| **指针碰撞** | 堆内存规整（复制、整理类 GC 后） | 用过的指针与空闲指针分界，分配即移动指针 |
| **空闲列表** | 堆不规整 | 维护空闲块列表，找合适块分配 |

**并发安全**：TLAB（Thread Local Allocation Buffer）—— 每个线程在 Eden 预分配一小块，多数对象在 TLAB 内无锁分配；TLAB 不够再同步分配。

## 2、对象内存布局

HotSpot 中对象在堆上分为三部分：

```
┌─────────────────────────────────────┐
│ 对象头 Header                        │
│  - Mark Word（哈希、GC 年龄、锁等）   │
│  - 类型指针（Klass Pointer）         │
│  - 数组长度（仅数组对象）             │
├─────────────────────────────────────┤
│ 实例数据 Instance Data               │
│  - 各字段，对齐填充影响顺序           │
├─────────────────────────────────────┤
│ 对齐填充 Padding                     │
│  - 保证对象大小为 8 字节的整数倍       │
└─────────────────────────────────────┘
```

### 2.1 Mark Word（64 位示例概念）

存储：哈希码、GC 分代年龄、锁状态、线程持有的锁、偏向锁 ID 等。同一时刻只存其中一部分，**根据对象状态复用**同一块 bits。

锁状态（简化）：无锁 → 偏向锁 → 轻量级锁 → 重量级锁。完整 Mark Word 位布局、升级路径、JDK 15+ 偏向锁废弃见 [10、锁与 synchronized 底层](./10、锁与synchronized底层.md)。

### 2.2 类型指针

指向方法区/元空间中类的元数据，JVM 据此确定对象是哪个类的实例。

**压缩指针**（默认开启 `-XX:+UseCompressedOops`）：在堆 < 32GB 时，将 64 位指针压缩为 32 位，节省内存。

### 2.3 实例数据

字段分配顺序受 **VM 策略**影响（如相同宽度字段放一起、父类字段在前），目的是**对齐**与**节省空间**。

### 2.4 对象大小估算（面试）

64 位 HotSpot，开启压缩指针、普通对象无数组：

- 对象头约 **12 字节**（Mark Word 8 + Klass 4）
- 字段按类型累加（int 4、long 8、引用 4…）
- 末尾 padding 到 8 的倍数

```java
// 空对象 Object o = new Object(); 约 16 字节（12 头 + 4 padding）
```

可用 `Instrumentation.getObjectSize()` 或 JOL（Java Object Layout）工具实测。

## 3、对象的访问定位

| 方式 | 说明 |
| ---- | ---- |
| **句柄** | 栈上 reference → 句柄池（对象实例数据 + 类型数据分离），GC 移动对象时只需改句柄 |
| **直接指针** | 栈上 reference → 堆中对象；HotSpot **默认**，访问更快 |

## 4、逃逸分析（Escape Analysis）

JIT 分析对象**是否逃出方法**（被其他线程或方法外引用）。

若**未逃逸**，可能优化：

| 优化 | 说明 |
| ---- | ---- |
| **栈上分配** | 对象在栈上分配，方法结束自动回收，减轻 GC |
| **标量替换** | 不创建对象，拆成若干局部变量 |
| **锁消除** | 对仅单线程使用的 synchronized 去锁 |

```java
public void noEscape() {
    Point p = new Point(1, 2); // 可能标量替换，不真正 new
    System.out.println(p.x + p.y);
}
```

开启：`-XX:+DoEscapeAnalysis`（HotSpot 默认开启）。**注意**：逃逸分析是 JIT 优化，非 javac 阶段；大量短生命周期小对象仍主要依赖 Eden + Minor GC。

## 5、Class 对象、对象、引用

| 概念 | 位置 | 说明 |
| ---- | ---- | ---- |
| `Class` 对象 | 堆（方法区元数据由 Class 对象关联） | 类加载产物，描述类结构 |
| 实例对象 | 堆 | `new` 创建 |
| reference 变量 | 栈局部变量表或堆字段 | 存对象地址（直接指针） |

```java
Person p = new Person();
// p：栈上 reference
// new Person()：堆上对象
// Person.class / getClass()：堆上 Class 对象
```

## 6、常见面试题

**1. 对象一定在堆上吗？**

规范上实例在堆；JIT 逃逸分析后可能**栈上分配或标量替换**，对程序员不可见。

**2. 为什么要有 padding？**

CPU 访问对齐后的内存更高效；HotSpot 要求对象大小为 8 字节倍数。

**3. 两个对象 hashCode 相同会冲突吗？**

`hashCode()` 可能冲突；`equals` 相等才表示同一逻辑对象。Mark Word 中哈希与锁信息会随状态变化。
