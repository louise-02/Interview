# 3、事务管理

## 1、Spring 事务抽象

`PlatformTransactionManager` 统一 JDBC、JPA、MyBatis 等：

- `DataSourceTransactionManager`
- `JpaTransactionManager`
- Boot 自动配置根据 classpath 选择

## 2、声明式事务 @Transactional

```java
@Transactional(rollbackFor = Exception.class)
public void transfer(Long from, Long to, BigDecimal amount) {
    accountDao.debit(from, amount);
    accountDao.credit(to, amount);
}
```

**默认**：仅 **RuntimeException / Error** 回滚；**checked Exception 不回滚** → 需 `rollbackFor`。

## 3、传播行为（Propagation）

| 行为 | 说明 |
| ---- | ---- |
| **REQUIRED**（默认） | 有事务加入，无则新建 |
| **REQUIRES_NEW** | 总是新建，挂起当前 |
| **NESTED** | 嵌套事务（Savepoint），外层回滚则内层也回滚 |
| **SUPPORTS** | 有则加入，无则非事务执行 |
| **NOT_SUPPORTED** | 非事务执行，挂起当前 |
| **MANDATORY** | 必须在事务内，否则异常 |
| **NEVER** | 必须无事务 |

## 4、隔离级别（Isolation）

与数据库一致：`DEFAULT`、`READ_UNCOMMITTED`、`READ_COMMITTED`、`REPEATABLE_READ`、`SERIALIZABLE`。

Spring 默认 `DEFAULT` = 使用数据库默认（MySQL InnoDB 为 RR）。

## 5、事务失效场景（面试高频）

| 场景 | 原因 |
| ---- | ---- |
| 方法非 **public** | 代理无法覆盖 |
| **同类 this 调用** | 未走代理 |
| 异常被 **catch 吞掉** | 未传播到代理 |
| **checked 异常**未配置 rollbackFor | 默认不回滚 |
| 类未被 Spring 管理 | 非 Bean |
| **数据库/引擎不支持** | 如 MyISAM |

## 6、编程式事务

`TransactionTemplate` 或 `PlatformTransactionManager` 手动 commit/rollback，少用，适合极小范围。

## 7、常见面试题

**1. REQUIRED 和 REQUIRES_NEW 区别？**

REQUIRED 共用一个事务；REQUIRES_NEW 独立提交/回滚，外层挂起。

**2. 如何保证多数据源事务？**

JTA 全局事务，或 Seata 等分布式事务；单数据源用 `@Transactional` 即可。

**3. @Transactional 原理？**

AOP + `TransactionInterceptor` 在方法前后开启/提交/回滚 Connection 事务。
