# 5、授权与方法安全

> `@EnableMethodSecurity` 与 `@PreAuthorize` 在生产方案里已启用，见 **[0、生产集成完整方案](./0、生产集成完整方案.md)**。

认证解决「你是谁」，授权解决「你能做什么」。

---

## 1、URL 级授权（粗粒度）

在 `SecurityFilterChain` 中（见 [2、Boot3与Security6配置](./2、Boot3与Security6配置.md)）：

```java
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/auth/**").permitAll()
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
    .requestMatchers(HttpMethod.DELETE, "/api/**").hasAuthority("system:delete")
    .anyRequest().authenticated())
```

| API | 说明 |
| --- | ---- |
| `hasRole("ADMIN")` | 等价 `hasAuthority("ROLE_ADMIN")` |
| `hasAuthority("order:approve")` | 细粒度权限字符串 |
| `hasAnyRole("ADMIN","USER")` | 多个角色之一 |
| `permitAll()` | 包括未登录匿名（视 Filter 而定） |
| `authenticated()` | 只要登录即可，不校验具体角色 |

## 2、方法级安全

### 开启

```java
@Configuration
@EnableMethodSecurity   // Security 6；旧版 @EnableGlobalMethodSecurity(prePostEnabled = true)
public class MethodSecurityConfig {
}
```

### 常用注解

```java
@PreAuthorize("hasRole('ADMIN')")
public void deleteUser(Long id) { }

@PreAuthorize("hasAuthority('order:approve')")
public void approve(Long orderId) { }

@PreAuthorize("#userId == authentication.principal.userId or hasRole('ADMIN')")
public UserVO getUser(Long userId) { }

@PostAuthorize("returnObject.owner == authentication.name")
public Order getOrder(Long id) { }

@Secured("ROLE_ADMIN")   // 旧式，不支持 SpEL 复杂表达式
public void adminOnly() { }
```

**`@PreAuthorize`** 最常用：方法执行**前**校验，失败抛 `AccessDeniedException` → 403。

### 与 URL 授权关系

- URL 没过 → 到不了 Controller  
- URL 过了 → 方法上还可再拦一层  
- 典型：**URL `authenticated()` + 方法 `@PreAuthorize` 细权限**

## 3、RBAC 模型（表设计思路）

```
用户 sys_user
  ↔ 用户角色 sys_user_role
角色 sys_role
  ↔ 角色权限 sys_role_permission
权限 sys_permission（permission 字符串：order:approve）
```

`UserDetailsService` 加载时把 role、permission 都转成 `GrantedAuthority` 放进 `Authentication`。

前端菜单树按角色过滤；后端 **必须以接口鉴权为准**，不能只看前端隐藏按钮。

## 4、动态权限（数据库驱动 URL）

菜单/按钮权限变化频繁时，可自定义 `AuthorizationManager` 或 Filter，从 DB 查「用户能否访问该 URL」。

思路：

```java
@Component
public class DynamicAuthorizationManager implements AuthorizationManager<RequestAuthorizationContext> {
    @Override
    public AuthorizationDecision check(Supplier<Authentication> authentication,
                                     RequestAuthorizationContext context) {
        String uri = context.getRequest().getRequestURI();
        // 查库：当前用户是否有 uri 权限
        boolean granted = permissionService.hasUrl(authentication.get(), uri);
        return new AuthorizationDecision(granted);
    }
}
```

```java
.authorizeHttpRequests(auth -> auth
    .anyRequest().access(dynamicAuthorizationManager))
```

复杂项目常用；简单项目 **角色 + @PreAuthorize** 够用。

## 5、SpEL 与 principal 类型

`@PreAuthorize` 表达式里：

- `authentication.name`：用户名  
- `authentication.principal`：若是自定义 `LoginUser`，可写 `authentication.principal.userId`  
- `@beanName.method()`：调 Spring Bean 做复杂判断  

需保证 `LoginUser` 字段与 SpEL 一致，否则启动或运行时报错。

## 6、403 vs 401 再强调

| | 401 Unauthorized | 403 Forbidden |
| - | ---------------- | ------------- |
| 含义 | 未登录 / Token 无效 | 已登录，权限不够 |
| 前端 | 跳登录 / 刷新 Token | 提示无权限 |

统一在 `exceptionHandling` 返回 JSON（见第 2 章）。

## 7、测试

```java
@Test
@WithMockUser(username = "admin", roles = "ADMIN")
void adminCanDelete() {
    // ...
}

@Test
@WithMockUser(username = "user", roles = "USER")
void userCannotDelete() {
    assertThrows(AccessDeniedException.class, () -> service.delete(1L));
}
```

集成测试可用 `@AutoConfigureMockMvc` + `mockMvc.perform(...).header("Authorization", "Bearer ...")`。
