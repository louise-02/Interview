# 知识体系总览

集成与类职责见 **[0、生产集成完整方案](./0、生产集成完整方案.md)**。本章是原理与选型的**速查**，适合集成跑通后复习，或面试前扫一眼。

## 1、Spring Security 是什么

Spring 生态里的**安全框架**，默认提供：

- **认证（Authentication）**：你是谁（登录、JWT、OAuth2）
- **授权（Authorization）**：你能干什么（角色、权限、URL、方法级）
- **防护**：CSRF、Session 固定、Headers 等（可按场景关闭或调整）

在 Servlet 应用里通过 **Filter 链** 工作，在方法上通过 **AOP + 注解** 工作。

---

## 2、核心对象（必记）

| 对象 | 含义 |
| ---- | ---- |
| `SecurityContext` | 当前线程的安全上下文，存 `Authentication` |
| `Authentication` | 认证信息：principal（用户）、credentials（凭证）、authorities（权限） |
| `SecurityContextHolder` | 用 `ThreadLocal` 取当前 `SecurityContext` |
| `UserDetails` | 用户详情接口，业务用户常实现或包装 |
| `UserDetailsService` | 按用户名加载用户（查库） |
| `PasswordEncoder` | 密码编码与校验（BCrypt） |
| `GrantedAuthority` | 权限项，如 `ROLE_ADMIN`、`user:delete` |
| `SecurityFilterChain` | **Security 6** 核心配置：一条 Filter 链 + 授权规则 |

---

## 3、请求大致怎么走

```
HTTP 请求
  → Servlet Filter 链（含 Spring Security 多个 Filter）
  → 认证成功后 Authentication 写入 SecurityContextHolder
  → AuthorizationFilter 判断 URL/方法是否允许
  → DispatcherServlet → Controller
  → @PreAuthorize 等方法安全（若有）
```

与 Spring MVC **Interceptor** 的关系：Security Filter 更靠前。见 [SpringMvc/3、拦截器过滤器与跨域](../6、SpringMvc/3、拦截器过滤器与跨域.md)。

## 4、版本对照

| | Boot 2.x | Boot 3.x |
| - | -------- | -------- |
| Spring Security | 5.7 / 5.8 | **6.x** |
| JDK | 8～17 | **17+** |
| 命名空间 | `javax.*` | **`jakarta.*** |
| 配置方式 | `WebSecurityConfigurerAdapter`（已废弃） | **`@Bean SecurityFilterChain`** |
| URL 授权 | `authorizeRequests()` + `antMatchers()` | **`authorizeHttpRequests()` + `requestMatchers()`** |

## 5、常见架构选型

| 场景 | 典型方案 |
| ---- | -------- |
| 前后端分离 + REST | 无 Session + JWT（见生产集成方案） |
| 微服务 | Gateway 鉴权 + 业务服务 JWT Filter |
| 第三方登录 | OAuth2/OIDC（见第 6 章） |
| 工作流 Activiti / Flowable | `SecurityContext` 用户 = 流程办理人；见 [Activiti/0、生产集成](../9、Activiti/0、生产集成完整方案.md) |
