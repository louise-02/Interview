# 1、微服务架构与组件选型

## 1、为什么微服务

| 优点 | 挑战 |
| ---- | ---- |
| 独立部署、技术异构、团队自治 | 分布式复杂度、运维、一致性 |
| 故障隔离、弹性扩缩 | 链路追踪、配置分散 |

**拆分原则**：高内聚、按业务能力、避免分布式单体（过度拆分）。

## 2、Spring Cloud 生态（常见）

| 能力 | Netflix（部分停更） | 常用替代 / Alibaba |
| ---- | ------------------- | ------------------ |
| 注册中心 | Eureka | **Nacos**、Consul |
| 配置中心 | — | **Nacos Config**、Apollo |
| 客户端负载均衡 | Ribbon（停更） | **Spring Cloud LoadBalancer** |
| 远程调用 | Feign | **OpenFeign** |
| 熔断限流 | Hystrix（停更） | **Sentinel**、Resilience4j |
| 网关 | Zuul | **Spring Cloud Gateway** |
| 分布式事务 | — | **Seata** |
| 链路追踪 | — | Sleuth + Zipkin / SkyWalking |

## 3、CAP 与 BASE

- **CAP**：Consistency、Availability、Partition tolerance 三者最多其二；分区下常 AP（最终一致）或 CP。
- **BASE**：Basically Available、Soft state、Eventually consistent。

注册中心 Nacos 支持 AP/CP 模式切换（临时实例 vs 持久实例）。

## 4、服务间通信

| 方式 | 说明 |
| ---- | ---- |
| 同步 HTTP/RPC | OpenFeign、gRPC |
| 异步消息 | Kafka、RabbitMQ（解耦、削峰） |

## 5、常见面试题

**1. 微服务和单体如何选择？**

团队规模、业务复杂度、运维能力；早期单体 + 模块化往往更合适。

**2. Eureka 和 Nacos 区别？**

Eureka AP 为主、停更；Nacos 注册+配置一体、支持 CP/AP。

**3. 什么是服务雪崩？**

下游故障导致线程阻塞、上游连锁失败 → 熔断、限流、降级。
