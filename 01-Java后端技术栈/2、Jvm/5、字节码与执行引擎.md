# 5、字节码与执行引擎

## 1、Class 文件结构（简要）

`.class` 是二进制，与 JVM 规范一一对应。

```
ClassFile {
    u4 magic;             // 0xCAFEBABE
    u2 minor_version;
    u2 major_version;
    u2 constant_pool_count;
    cp_info constant_pool[...];  // 常量池
    u2 access_flags;
    u2 this_class;
    u2 super_class;
    u2 interfaces_count;
    u2 fields_count;
    u2 methods_count;
    u2 attributes_count;
}
```

**常量池**：字面量（字符串、final 常量值）+ 符号引用（类/字段/方法的全限定名与描述符）。

**常量池主要条目类型**

| 类型 | 示例 |
| ---- | ---- |
| CONSTANT_Utf8 | 字符串字面量 |
| CONSTANT_Integer / Float / Long / Double | 数值常量 |
| CONSTANT_Class | 类符号引用 |
| CONSTANT_Fieldref / Methodref / InterfaceMethodref | 字段、方法引用 |
| CONSTANT_NameAndType | 名称 + 描述符 |
| CONSTANT_MethodHandle / MethodType / InvokeDynamic | JDK 7+ 动态调用 |

**描述符**：方法 `(I)V` 表示 int 参数 void 返回；`Ljava/lang/String;` 表示 String 引用。

**重要 Attributes**

| 属性 | 说明 |
| ---- | ---- |
| **Code** | 方法字节码、异常表、max_stack、max_locals |
| **LineNumberTable** | 行号 ↔ 字节码偏移（调试、异常栈） |
| **LocalVariableTable** | 局部变量名（`-g` 编译才有） |
| **StackMapTable** | JDK 7+ 类型检查验证，替代逐条校验 |
| **BootstrapMethods** | invokedynamic 引导方法 |
| **InnerClasses** | 内部类信息 |

查看工具：`javap -v Foo.class`、IDEA 反编译、ASM、Byte Buddy。

## 2、字节码指令分类

HotSpot 执行引擎基于**操作数栈**（非寄存器）。

| 类型 | 示例 | 说明 |
| ---- | ---- | ---- |
| 加载存储 | `iload`、`aload`、`istore` | 局部变量表 ↔ 操作数栈 |
| 运算 | `iadd`、`lmul` | 栈顶运算 |
| 类型转换 | `i2l`、`f2d` | 宽化/窄化 |
| 对象创建与访问 | `new`、`getfield`、`putfield`、`invokevirtual` | |
| 操作数栈管理 | `dup`、`pop`、`swap` | |
| 控制转移 | `ifeq`、`goto` | 分支、循环 |
| 方法调用与返回 | `invokestatic`、`invokeinterface`、`ireturn` | |
| 同步 | `monitorenter`、`monitorexit` | synchronized 底层 |

**方法调用指令**

| 指令 | 说明 |
| ---- | ---- |
| `invokestatic` | 静态方法 |
| `invokespecial` | 构造器、private、super 方法 |
| `invokevirtual` | 虚方法，多态 |
| `invokeinterface` | 接口方法 |
| `invokedynamic` | Lambda、方法引用等（JDK 7+） |

## 3、解释执行与 JIT

```
字节码
  → 解释器（Interpreter）逐条执行，启动快
  → 热点代码被 JIT 编译为本地机器码，执行快
  → 分层编译（Tiered Compilation）：C1 快速编译 + C2 深度优化
```

**热点探测**：方法调用计数器、回边计数器（循环）。

| 模式 | 参数 | 说明 |
| ---- | ---- | ---- |
| 解释 | `-Xint` | 仅解释 |
| 编译 | `-Xcomp` | 启动时全量编译，启动慢 |
| 混合 | 默认 | 解释 + JIT |

**OSR（On-Stack Replacement）**：循环体编译替换，避免等整个方法执行完再切换本地代码。

## 4、编译优化（JIT）

| 优化 | 说明 |
| ---- | ---- |
| **方法内联** | 将小方法 callee 展开到 caller，减少栈帧与调用开销 |
| **逃逸分析** | 见第 3 章 |
| **锁消除** | 无竞争 synchronized 去锁 |
| **标量替换** | 见第 3 章 |
| **空值检查消除** | 合并或外提检查 |

**去优化（Deoptimization）**：假设失效（如类层次变化）时回退到解释执行。

**`-XX:ReservedCodeCacheSize`**：JIT 代码缓存，过小会导致 JIT 停止编译。详见第 2 章 Code Cache。

**C1 / C2 编译器**

| 编译器 | 别名 | 特点 |
| ------ | ---- | ---- |
| **C1** | Client Compiler | 快速编译，优化少 |
| **C2** | Server Compiler | 深度优化，编译慢 |

**分层编译 Tiered Compilation**（默认）：0 解释 → 3 C1 全量 → 4 C1 分析 → 2 C1 受限 → 1 C2。

**`-XX:CompileThreshold`**：方法/循环触发 C2 的计数阈值。

## 5、静态绑定 vs 动态绑定

| 绑定 | 时机 | 典型 |
| ---- | ---- | ---- |
| **静态 / 早期** | 编译期确定 | static、private、final、构造器 |
| **动态 / 晚期** | 运行期确定 | 虚方法重写、接口默认方法 |

**虚方法表（vtable）**：类加载时生成，对象调用 invokevirtual 时查表；接口用 **itable**。

## 6、Native 方法与 JNI

`native` 方法由 **JNI** 调用 C/C++ 实现，执行时在**本地方法栈**登记，通过 **JNI 本地方法接口** 与 Java 交互。

适用：操作系统 API、高性能计算、已有 C 库复用。注意 JNI 调用有**额外开销**，不宜频繁跨边界。

**JNI 与 JVM 交互**

- `RegisterNatives`：注册 native 方法，跳过名称解析。
- **局部引用 / 全局引用**：Native 代码持有 Java 对象需正确释放，否则泄漏。
- **Attach 当前线程**：Native 回调中需 `AttachCurrentThread` 才能调 Java API。

## 7、栈深度与字节码验证

- **`max_stack`**：操作数栈最大深度（Code 属性）。
- **`max_locals`**：局部变量表 Slot 数。
- **StackMapTable**：类型安全验证，加速类加载验证阶段。

## 8、常见面试题

**1. Java 是解释执行还是编译执行？**

两者兼有：字节码 + 解释器 + JIT 编译本地代码。

**2. 重载与重写对方法调用的影响？**

重载：编译期根据静态类型选方法。重写：运行时根据实际对象类型（虚方法调用）。

**3. `invokedynamic` 用来干什么？**

支持动态语言特性；Lambda 表达式不生成大量 synthetic 类，而是通过 `invokedynamic` + LambdaMetafactory 生成调用点。

**4. 如何查看 JIT 编译情况？**

`-XX:+PrintCompilation`；JDK 9+ `-Xlog:jit+compilation`；JFR、JITWatch 等。
