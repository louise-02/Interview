默认用 **`@Transactional` 声明式**；当要在代码里**手动控制**提交/回滚、或注册**事务完成后的回调**时，用 **`PlatformTransactionManager`** 编程式事务。

---

# 1、依赖与配置

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>
<!-- 或 mybatis-plus-boot-starter，与编程式事务共用同一 DataSource -->
```

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: root
    driver-class-name: com.mysql.cj.jdbc.Driver
```

Spring Boot 会自动配置 **`PlatformTransactionManager`**（底层一般是 `DataSourceTransactionManager`），直接注入即可。

# 2、PlatformTransactionManager 手动控制（核心写法）

```java
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.TransactionDefinition;
import org.springframework.transaction.TransactionStatus;

@Service
public class AccountService {

    @Resource
    private PlatformTransactionManager platformTransactionManager;

    @Resource
    private TransactionDefinition transactionDefinition;

    @Resource
    private AccountMapper accountMapper;

    public void transfer(Long fromId, Long toId, BigDecimal amount) {
        // 1. 开启事务
        TransactionStatus transactionStatus =
                platformTransactionManager.getTransaction(transactionDefinition);

        try {
            int rows = accountMapper.decreaseBalance(fromId, amount);
            if (rows == 0) {
                throw new BusinessException(400, "余额不足");
            }
            accountMapper.increaseBalance(toId, amount);

            // 2. 提交
            platformTransactionManager.commit(transactionStatus);
        } catch (Exception e) {
            // 3. 回滚（仅当事务仍 active 时）
            if (!transactionStatus.isCompleted()) {
                platformTransactionManager.rollback(transactionStatus);
            }
            throw e;
        }
    }
}
```

**三个核心对象**

| 对象 | 作用 |
| ---- | ---- |
| `PlatformTransactionManager` | 事务管理器：`getTransaction` / `commit` / `rollback` |
| `TransactionDefinition` | 事务属性：传播行为、隔离级别、超时、是否只读 |
| `TransactionStatus` | 当前事务状态：是否新事务、是否只读、是否已完成 |

**注册 TransactionDefinition Bean**（注入 `transactionDefinition` 时需要）：

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.transaction.TransactionDefinition;
import org.springframework.transaction.support.DefaultTransactionDefinition;

@Configuration
public class TransactionConfig {

    @Bean
    public TransactionDefinition transactionDefinition() {
        DefaultTransactionDefinition def = new DefaultTransactionDefinition();
        def.setPropagationBehavior(TransactionDefinition.PROPAGATION_REQUIRED);
        def.setIsolationLevel(TransactionDefinition.ISOLATION_DEFAULT);
        def.setTimeout(30);       // 秒，-1 表示不超时
        def.setReadOnly(false);
        return def;
    }
}
```

也可以在方法内临时创建，适合单次特殊配置：

```java
DefaultTransactionDefinition def = new DefaultTransactionDefinition();
def.setPropagationBehavior(TransactionDefinition.PROPAGATION_REQUIRES_NEW);
TransactionStatus status = platformTransactionManager.getTransaction(def);
```

# 3、事务完成后注册回调（TransactionSynchronization）

事务提交或回滚**之后**还要做的事（发 MQ、清缓存、发通知），用 **`TransactionSynchronizationManager.registerSynchronization`**：

```java
import org.springframework.transaction.support.TransactionSynchronization;
import org.springframework.transaction.support.TransactionSynchronizationManager;

public void createOrder(OrderCreateRequest request) {
    TransactionStatus transactionStatus =
            platformTransactionManager.getTransaction(transactionDefinition);

    try {
        orderMapper.insert(order);
        stockMapper.decrease(request.getStockId(), request.getQty());

        // 必须在 commit 之前、且当前存在活跃事务时注册
        TransactionSynchronizationManager.registerSynchronization(
                new TransactionSynchronization() {

                    @Override
                    public void afterCommit() {
                        // 事务提交成功后执行（最常用）
                        // 如：发送 MQ、删除 Redis 缓存、异步通知
                        mqProducer.send("order.created", order.getId());
                    }

                    @Override
                    public void afterCompletion(int status) {
                        // 事务完成后执行（提交或回滚都会走）
                        // status：STATUS_COMMITTED / STATUS_ROLLED_BACK / STATUS_UNKNOWN
                        log.info("事务结束，status={}", status);
                    }

                    @Override
                    public void beforeCommit(boolean readOnly) {
                        // 提交前回调（少用）
                    }

                    @Override
                    public void afterRollback() {
                        // 回滚后回调
                        log.warn("订单创建失败，已回滚");
                    }
                }
        );

        platformTransactionManager.commit(transactionStatus);
    } catch (Exception e) {
        if (!transactionStatus.isCompleted()) {
            platformTransactionManager.rollback(transactionStatus);
        }
        throw e;
    }
}
```

**注意**

| 点 | 说明 |
| -- | ---- |
| 注册时机 | 必须在 **`commit` 之前**、且处于活跃事务中调用 |
| `afterCommit` | 只有**提交成功**才执行；适合发 MQ，避免 DB 回滚了消息已发出 |
| 无事务时 | 未开启事务就 `registerSynchronization` 会抛 `IllegalStateException` |
| 声明式等价 | `@TransactionalEventListener(phase = AFTER_COMMIT)` 是更高层的「提交后执行」方案 |

**声明式事务下的等价写法**（对比参考）：

```java
// 事件
public record OrderCreatedEvent(Long orderId) {}

// 监听：事务提交后才执行
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void onOrderCreated(OrderCreatedEvent event) {
    mqProducer.send("order.created", event.orderId());
}
```

# 4、setRollbackOnly 标记回滚

不想抛异常、但仍要回滚时：

```java
TransactionStatus transactionStatus =
        platformTransactionManager.getTransaction(transactionDefinition);

try {
    if (someBusinessCheckFailed) {
        transactionStatus.setRollbackOnly();   // 标记回滚
        return;
    }
    accountMapper.update(...);
    platformTransactionManager.commit(transactionStatus);
    // 已 setRollbackOnly 时，commit 实际会走 rollback
} catch (Exception e) {
    if (!transactionStatus.isCompleted()) {
        platformTransactionManager.rollback(transactionStatus);
    }
    throw e;
}
```

# 5、TransactionTemplate（简化写法，可选）

不想手写 commit/rollback 时，可用 `TransactionTemplate` 包装：

```java
@Resource
private TransactionTemplate transactionTemplate;

public void transfer(Long fromId, Long toId, BigDecimal amount) {
    transactionTemplate.executeWithoutResult(status -> {
        int rows = accountMapper.decreaseBalance(fromId, amount);
        if (rows == 0) {
            status.setRollbackOnly();
            throw new BusinessException(400, "余额不足");
        }
        accountMapper.increaseBalance(toId, amount);
    });
}
```

| 对比 | PlatformTransactionManager 手动 | TransactionTemplate |
| ---- | --------------------------------- | ------------------- |
| 控制粒度 | 完全手动 commit/rollback | 回调内自动提交/回滚 |
| 注册 Synchronization | 灵活，可在 commit 前注册 | 同样可在 execute 内 registerSynchronization |
| 适用 | 需要精确控制流程 | 逻辑简单、代码更短 |

# 6、传播行为

```java
DefaultTransactionDefinition def = new DefaultTransactionDefinition();
def.setPropagationBehavior(TransactionDefinition.PROPAGATION_REQUIRES_NEW);
TransactionStatus status = platformTransactionManager.getTransaction(def);
```

| 传播 | 含义 |
| ---- | ---- |
| REQUIRED（默认） | 有事务就加入，没有就新建 |
| REQUIRES_NEW | 挂起外层，新建独立事务 |
| NESTED | 保存点嵌套，外层回滚则内层也回滚 |
| NOT_SUPPORTED | 挂起事务，非事务执行 |

# 7、与 @Transactional 对比

| | @Transactional | PlatformTransactionManager |
| -- | -------------- | -------------------------- |
| 写法 | 注解，AOP | 代码显式控制 |
| 适用 | 整方法一个边界 | 方法内分支、循环、精确 commit 时机 |
| 自调用 | 同类 `this.method()` **不生效** | 不受 AOP 限制 |
| 提交后回调 | `@TransactionalEventListener` | `TransactionSynchronization.afterCommit` |

**同类自调用失效**：

```java
@Service
public class BadService {
    public void outer() {
        this.inner();   // 不走代理，@Transactional 无效
    }
    @Transactional
    public void inner() { }
}
```

解决：注入自身代理、改用编程式事务、或 `TransactionTemplate`。

# 8、MyBatis-Plus 场景

编程式事务与 Mapper 共用同一 `DataSource`，事务边界放在 Service：

```java
TransactionStatus status = platformTransactionManager.getTransaction(transactionDefinition);
try {
    orderMapper.insert(order);
    stockMapper.decrease(stockId, qty);
    platformTransactionManager.commit(status);
} catch (Exception e) {
    if (!status.isCompleted()) {
        platformTransactionManager.rollback(status);
    }
    throw e;
}
```

不要在事务里做长 IO（调 HTTP、睡线程），会**长时间占连接**。

# 9、常见坑

| 点 | 说明 |
| -- | ---- |
| 异常吞噬 | `catch` 后不抛、不 `rollback`、不 `setRollbackOnly` 会**误提交** |
| 重复 rollback | `commit` 失败后 `status` 可能已 completed，回滚前判断 `!status.isCompleted()` |
| 只读 | `def.setReadOnly(true)` 优化只读查询 |
| 多数据源 | 需指定对应 `PlatformTransactionManager` |
| afterCommit 里再开 DB 事务 | 已是新连接/新事务，与当前事务无关 |

# 10、验证回滚

```sql
CREATE TABLE account (
  id BIGINT PRIMARY KEY,
  balance DECIMAL(10,2) NOT NULL
);
INSERT INTO account VALUES (1, 100), (2, 50);
```

故意转账金额超过余额 → `commit` 不应执行，两条 UPDATE 都应回滚，余额与执行前一致。
