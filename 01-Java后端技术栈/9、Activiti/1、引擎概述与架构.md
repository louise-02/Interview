# 1、引擎概述与架构

> 生产要建哪些类、BPMN 放哪，见 **[0、生产集成完整方案](./0、生产集成完整方案.md)**。本章讲原理。

## 1、工作流引擎解决什么

把**长周期、多角色、有顺序**的业务（请假、报销、采购）从 if-else 状态机里拆出来：

- 流程结构 → **BPMN 图**（可视化、可版本化）
- 谁办理 → **User Task** + assignee / candidate
- 系统动作 → **Service Task** + JavaDelegate
- 审批轨迹 → 引擎**历史表**自动记录

## 2、Flowable 与 Activiti

| | Activiti | Flowable |
| - | -------- | -------- |
| 渊源 | Alfresco 开源 BPMN 引擎 | Activiti 核心团队 2016 分支 |
| 现状 | Activiti 7 仍维护 | **Boot 3 生态更常用 Flowable 7** |
| API | `org.activiti.engine.*` | `org.flowable.engine.*` |
| 概念 | RuntimeService、TaskService、BPMN 2.0 | **同名同构** |

面试和旧项目说「Activiti」时，多半指这类引擎；**集成代码按实际依赖选包名**即可。

## 3、七大 Service（必记）

| Service | 职责 |
| ------- | ---- |
| **RepositoryService** | 部署 BPMN、查流程定义（ProcessDefinition） |
| **RuntimeService** | 启动/删除流程实例、设变量 |
| **TaskService** | 用户任务：查询、签收、完成 |
| **HistoryService** | 已结束实例、历史任务、审批时间线 |
| **IdentityService** | 引擎内置用户/组（可选，可与 RBAC 映射） |
| **ManagementService** | 引擎管理、Job、数据库表信息 |
| **FormService** | 动态表单（用得少，多前后端分离自定义表单） |

生产 HTTP 层主要用前四个。

---

## 4、核心概念关系

```
ProcessDefinition（流程定义，部署一次）
    └── ProcessInstance（一次运行，如张三的请假单）
            └── Execution（执行流，并行网关会有多条）
                    └── Task（用户任务，待办列表里的一行）
```

- **businessKey**：业务单号，启动时传入，方便和业务表关联  
- **variables**：流程变量，JSON 可序列化类型；网关条件、assignee 表达式都读它

## 5、数据库表（了解）

Flowable / Activiti 表前缀一般为 **`ACT_`**（Flowable 部分新表也有 `FLW_`）：

| 前缀 | 含义 |
| ---- | ---- |
| `ACT_RE_*` | Repository：定义、部署 |
| `ACT_RU_*` | Runtime：运行中实例、任务 |
| `ACT_HI_*` | History：历史 |
| `ACT_ID_*` | Identity：用户组（若用） |
| `ACT_GE_*` | General：通用资源 |

**同库部署**：与业务表共用一个 DataSource，配置 `database-schema-update` 自动建表（生产受控 DDL）。

## 6、与「状态模式 / 策略模式」的分工

| 层次 | 适合 |
| ---- | ---- |
| **BPMN 引擎** | 多节点、多角色、要图、要审计轨迹 |
| **状态模式** | 单实体简单状态机（订单：待支付→已支付） |
| **策略模式** | 某一节点内多种算法（不同请假类型计算天数） |

复杂流程：**BPMN 管编排**，节点内用 **策略** 处理业务分支，见 [4、节点扩展](./4、节点扩展Delegate与Listener.md)。
