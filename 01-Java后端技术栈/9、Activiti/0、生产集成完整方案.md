# 生产集成完整方案

**Spring Boot 3 + Flowable 7 + MySQL + Spring Security（JWT）** 的工作流集成。示例业务：**请假流程**（提交 → 主管审批 → 结束）。

> **引擎说明**：Spring Boot 3 推荐 **Flowable 7**（`flowable-spring-boot-starter`）。Flowable 由 Activiti 6 分支演进，**`RuntimeService` / `TaskService` / BPMN 概念与 Activiti 同源**；老项目若为 `org.activiti.engine.*`，替换 import 即可。下文统一写 Flowable。

先按本章把**依赖、BPMN、类、接口**搭齐；引擎表结构、网关原理见 [1～5 章](#10、原理深入学习阅读顺序)。

**前置**：[Spring Security 生产集成](../8、SpringSecurity/0、生产集成完整方案.md)（JWT 已通）。

---

## 1、方案说明

| 项 | 选型 |
| -- | ---- |
| 引擎 | Flowable 7.x（Activiti 同源 API） |
| 流程定义 | BPMN 2.0 XML，放 `classpath:processes/` |
| 数据库 | 与业务库**同库**（`ACT_*` 表自动建）或独立 schema |
| 当前用户 | **Spring Security** `SecurityUtils.getUsername()`，不单独维护工作流登录态 |
| 待办查询 | assignee + candidateUser + candidateGroup（与 RBAC 组名对齐） |
| 办理鉴权 | Controller 层校验「能否办理该 taskId」 |
| 业务扩展 | **JavaDelegate**（自动节点）、**TaskListener**（任务前后） |

---

## 2、请求链路

```
POST /api/workflow/process/leave/start  (Bearer)
  → JwtAuthenticationFilter 恢复 SecurityContext
  → ProcessController → ProcessAppService
  → runtimeService.startProcessInstanceByKey("leave_process", businessKey, variables)
  → 首节点 assignee = 当前用户

GET /api/workflow/tasks/todo  (Bearer)
  → TaskAppService：按当前 userId + 角色组查待办
  → taskService.createTaskQuery()...

POST /api/workflow/tasks/{taskId}/complete  (Bearer)
  → 校验 canHandle(task, userId)
  → taskService.complete(taskId, variables)
  → 流程流转到下一节点或结束
```

## 4、包结构与类职责一览

```
com.example.xxx
├── config
│   └── FlowableConfig.java              # 可选：异步线程池、流程图字体
├── controller
│   ├── ProcessController.java           # 启动流程、查实例
│   └── TaskController.java              # 待办、签收、办理
├── workflow
│   ├── ProcessAppService.java           # 封装 RuntimeService
│   ├── TaskAppService.java              # 封装 TaskService + 待办查询
│   ├── TaskPermissionService.java       # canHandle：assignee/candidate 校验
│   └── dto/                             # StartLeaveDTO、CompleteTaskDTO
├── delegate
│   └── NotifyManagerDelegate.java       # Service Task：发通知等
└── listener
    └── ProcessEndListener.java          # 流程结束写业务状态
```

| 类 | 做什么 |
| -- | ------ |
| **FlowableConfig** | 按需注册 `AsyncListenableTaskExecutor`；中文流程图防乱码设 `activityFontName` |
| **ProcessController** | HTTP：启动请假、查询我发起的流程 |
| **TaskController** | HTTP：待办列表、签收 claim、办理 complete |
| **ProcessAppService** | 组装流程变量、调 `runtimeService.startProcessInstanceByKey` |
| **TaskAppService** | 待办/已办查询、complete、claim；**不要**与引擎 `TaskService` 同名 |
| **TaskPermissionService** | 办理前 **必须** 校验权限，防止越权办别人的任务 |
| **NotifyManagerDelegate** | BPMN 里 `flowable:delegateExpression="${notifyManagerDelegate}"` 调用的 Bean |
| **ProcessEndListener** | 流程结束时更新业务表（如请假单状态） |

引擎自动注入的 Bean（直接用 `@Resource`）：

| Bean | 用途 |
| ---- | ---- |
| `RuntimeService` | 启动、删实例、设变量 |
| `TaskService` | 待办、签收、完成 |
| `HistoryService` | 已办、审批轨迹 |
| `RepositoryService` | 部署/查询流程定义 |
| `IdentityService` | 可选：用户组同步 |

## 5、application.yml

```yaml
spring:
  datasource:
    # 与业务共库即可；Flowable 启动时会建/更新 ACT_* 表
    url: jdbc:mysql://localhost:3306/app?useUnicode=true&characterEncoding=utf8&nullCatalogMeansCurrent=true
    username: root
    password: xxx                         # 生产用配置中心

# Flowable 引擎配置
flowable:
  # 是否自动建表/升级表结构：开发 true；生产首次上线后可改 false，DDL 走审核脚本
  database-schema-update: true
  # 异步 Service Task、定时器依赖后台 Job 线程池，不开则异步节点可能卡住
  async-executor-activate: true
  # 启动时扫描并部署 classpath:processes/*.bpmn20.xml
  check-process-definitions: true

logging:
  level:
    org.flowable: INFO                    # 排查流程/任务问题时可改 DEBUG
```

生产建议：`database-schema-update: false`，DDL 用官方脚本或 DBA 审核后执行。

## 6、BPMN 流程文件

路径：`src/main/resources/processes/leave_process.bpmn20.xml`（文件名后缀 `.bpmn20.xml` 才会被自动部署）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<definitions xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
             xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
             xmlns:flowable="http://flowable.org/bpmn"
             targetNamespace="http://www.flowable.org/processdef">

  <!-- process id = 代码里 startProcessInstanceByKey 的第一个参数 -->
  <process id="leave_process" name="请假流程" isExecutable="true">

    <startEvent id="start"/>
    <sequenceFlow sourceRef="start" targetRef="applyTask"/>

    <!-- User Task：办理人来自流程变量 applyUserId（启动流程时 vars.put） -->
    <userTask id="applyTask" name="提交请假"
              flowable:assignee="${applyUserId}"/>
    <sequenceFlow sourceRef="applyTask" targetRef="managerTask"/>

    <!-- candidateGroups：组名与 Spring Security ROLE 映射见 TaskPermissionService.resolveGroups -->
    <userTask id="managerTask" name="主管审批"
              flowable:candidateGroups="dept_manager"/>
    <sequenceFlow sourceRef="managerTask" targetRef="approveGateway"/>

    <!-- 排他网关：只走满足条件的一条线 -->
    <exclusiveGateway id="approveGateway"/>
    <sequenceFlow sourceRef="approveGateway" targetRef="notifyApproved">
      <!-- complete 时传入 approved=true 走这条 -->
      <conditionExpression xsi:type="tFormalExpression"><![CDATA[${approved == true}]]></conditionExpression>
    </sequenceFlow>
    <sequenceFlow sourceRef="approveGateway" targetRef="notifyRejected">
      <conditionExpression xsi:type="tFormalExpression"><![CDATA[${approved == false}]]></conditionExpression>
    </sequenceFlow>

    <!-- Service Task：自动执行 JavaDelegate，不人工待办 -->
    <serviceTask id="notifyApproved" name="通知通过"
                 flowable:delegateExpression="${notifyManagerDelegate}"/>
    <sequenceFlow sourceRef="notifyApproved" targetRef="endApproved"/>

    <serviceTask id="notifyRejected" name="通知驳回"
                 flowable:delegateExpression="${notifyManagerDelegate}"/>
    <sequenceFlow sourceRef="notifyRejected" targetRef="endRejected"/>

    <endEvent id="endApproved"/>
    <endEvent id="endRejected"/>

  </process>
</definitions>
```

`process id="leave_process"` = 代码里 `startProcessInstanceByKey("leave_process")` 的 key。

### 7.2 TaskPermissionService

```java
// 办理/签收前校验：当前用户是否是 assignee 或 candidate，防止越权 complete
@Service
@RequiredArgsConstructor
public class TaskPermissionService {

    // 注意：引擎自带 org.flowable.engine.TaskService，应用层类不要同名
    private final org.flowable.engine.TaskService taskService;

    public boolean canHandle(String taskId, String userId, Collection<String> groupIds) {
        Task task = taskService.createTaskQuery().taskId(taskId).singleResult();
        if (task == null) {
            return false;  // 任务不存在或已完成
        }
        // 已是明确办理人
        if (userId.equals(task.getAssignee())) {
            return true;
        }
        // 在候选人列表里（尚未 claim）
        if (taskService.createTaskQuery().taskId(taskId).taskCandidateUser(userId).count() > 0) {
            return true;
        }
        // 在候选组里（组名与 BPMN candidateGroups 一致）
        if (groupIds != null && !groupIds.isEmpty()
            && taskService.createTaskQuery().taskId(taskId)
                .taskCandidateGroupIn(groupIds).count() > 0) {
            return true;
        }
        return false;
    }

    // 把 Spring Security 的 ROLE_DEPT_MANAGER 转成 BPMN 组名 dept_manager
    public Collection<String> resolveGroups(Authentication auth) {
        if (auth == null) return List.of();
        return auth.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .map(a -> a.startsWith("ROLE_") ? a.substring(5).toLowerCase() : a)
            .toList();
    }
}
```

### 7.3 ProcessAppService

```java
// 封装「启动流程、查我发起的实例」，Controller 不直接调 RuntimeService
@Service
@RequiredArgsConstructor
public class ProcessAppService {

    private final RuntimeService runtimeService;   // 运行中流程实例
    private final HistoryService historyService;   // 已结束轨迹（myStarted 可改用 history 查）

    public String startLeave(LeaveStartDTO dto) {
        // 发起人 = 当前 JWT 用户（SecurityContext）
        String userId = SecurityUtils.getLoginUser().getUsername();
        Map<String, Object> vars = new HashMap<>();
        vars.put("applyUserId", userId);           // BPMN assignee="${applyUserId}"
        vars.put("days", dto.getDays());
        vars.put("reason", dto.getReason());
        vars.put("businessKey", dto.getBusinessKey());

        // 第二参数 businessKey：业务单号，方便和业务表互查
        ProcessInstance pi = runtimeService.startProcessInstanceByKey(
            "leave_process",              // 对应 BPMN process id
            dto.getBusinessKey(),
            vars);
        return pi.getProcessInstanceId(); // 回写业务表 process_instance_id
    }

    public List<ProcessInstanceVO> myStarted() {
        String userId = SecurityUtils.getLoginUser().getUsername();
        return runtimeService.createProcessInstanceQuery()
            .variableValueEquals("applyUserId", userId)  // 按流程变量筛「我发起的」
            .list()
            .stream()
            .map(/* 转 VO：instanceId、businessKey、当前节点 */)
            .toList();
    }
}
```

### 7.4 TaskAppService

```java
// 封装待办、签收、办理；类名勿叫 TaskService，避免和引擎 Bean 冲突
@Service
@RequiredArgsConstructor
public class TaskAppService {

    private final org.flowable.engine.TaskService taskService;
    private final TaskPermissionService taskPermissionService;

    public List<TaskVO> todoList(Authentication auth) {
        String userId = auth.getName();
        Collection<String> groups = taskPermissionService.resolveGroups(auth);

        // or：已指定给我 / 我是候选人 / 我所在组是候选组，三种待办合并查
        List<Task> tasks = taskService.createTaskQuery()
            .or()
            .taskAssignee(userId)
            .taskCandidateUser(userId)
            .taskCandidateGroupIn(groups.isEmpty() ? List.of("__none__") : groups)  // 无组时占位，避免语法错误
            .endOr()
            .orderByTaskCreateTime().desc()
            .list();

        return tasks.stream().map(/* 转 VO：taskId、name、processInstanceId */).toList();
    }

    // candidate 任务：先 claim 把 assignee 设为自己，再 complete
    public void claim(String taskId, Authentication auth) {
        String userId = auth.getName();
        if (!taskPermissionService.canHandle(taskId, userId,
                taskPermissionService.resolveGroups(auth))) {
            throw new AccessDeniedException("无权签收");
        }
        taskService.claim(taskId, userId);
    }

    public void complete(String taskId, Map<String, Object> vars, Authentication auth) {
        String userId = auth.getName();
        if (!taskPermissionService.canHandle(taskId, userId,
                taskPermissionService.resolveGroups(auth))) {
            throw new AccessDeniedException("无权办理");
        }
        // vars 如 approved、comment 会写入流程实例，供网关条件、后续节点使用
        taskService.complete(taskId, vars);
    }
}
```

### 7.5 ProcessController / TaskController

```java
@RestController
@RequestMapping("/api/workflow/process")
@RequiredArgsConstructor
public class ProcessController {

    private final ProcessAppService processAppService;

    @PostMapping("/leave/start")
    public Result start(@RequestBody LeaveStartDTO dto) {
        return Result.ok(Map.of("processInstanceId", processAppService.startLeave(dto)));
    }
}

@RestController
@RequestMapping("/api/workflow/tasks")
@RequiredArgsConstructor
public class TaskController {

    private final TaskAppService taskAppService;

    @GetMapping("/todo")
    public Result todo(Authentication auth) {
        return Result.ok(taskAppService.todoList(auth));
    }

    @PostMapping("/{taskId}/claim")
    public Result claim(@PathVariable String taskId, Authentication auth) {
        taskAppService.claim(taskId, auth);
        return Result.ok();
    }

    @PostMapping("/{taskId}/complete")
    public Result complete(@PathVariable String taskId,
                           @RequestBody CompleteTaskDTO dto,
                           Authentication auth) {
        // 主管审批时 body 传 approved=true/false，见 §8 接口约定
        taskAppService.complete(taskId, dto.toVariables(), auth);
        return Result.ok();
    }
}
```

`/api/workflow/**` 不要放进 Security 白名单，与其它 `/api/**` 一样走 JWT。任务能否办理靠 **`TaskPermissionService.canHandle`**，详见 [5、与SpringSecurity集成](./5、与SpringSecurity集成.md)。

### 7.6 NotifyManagerDelegate

```java
// BPMN serviceTask 的 delegateExpression="${notifyManagerDelegate}" 指向本 Bean
@Component("notifyManagerDelegate")
@RequiredArgsConstructor
public class NotifyManagerDelegate implements JavaDelegate {

    private final LeaveNotifyService leaveNotifyService;

    @Override
    public void execute(DelegateExecution execution) {
        // 业务单号：启动流程时传的 businessKey
        String businessKey = execution.getProcessInstanceBusinessKey();
        // 上一 User Task complete 时传入的 approved
        Boolean approved = (Boolean) execution.getVariable("approved");
        leaveNotifyService.sendResult(businessKey, Boolean.TRUE.equals(approved));
        // 引擎异步线程，无 HTTP SecurityContext，不要在这里取当前登录用户
    }
}
```

### 7.7 业务表与流程关联（推荐）

| 字段 | 说明 |
| ---- | ---- |
| `business_key` | 业务单号，启动流程时传入，与 `ProcessInstance.businessKey` 一致 |
| `process_instance_id` | 引擎实例 ID，便于追溯 |
| `status` | 业务状态（DRAFT / APPROVING / APPROVED / REJECTED） |

流程启动后写 `process_instance_id`；`ProcessEndListener` 或 Delegate 里更新 `status`。

## 8、接口约定

| 接口 | 说明 |
| ---- | ---- |
| `POST /api/workflow/process/leave/start` | body: `{ businessKey, days, reason }` |
| `GET /api/workflow/tasks/todo` | 当前用户待办 |
