# 1、概述

Kafka 默认语义是 **至少一次（at-least-once）**：

| 现象 | 含义 |
|------|------|
| **丢消息** | 消息没进 Kafka，或消费了但业务没处理完 |
| **重复消费** | 同一条业务消息被处理多次 |

**精确一次（exactly-once）** 主要指 Producer 写 Kafka 或 Consume-Transform-Produce 事务；业务上「只扣一次款」仍要靠 **应用层幂等**。

配置分三层：

```text
Producer  → spring.kafka.producer
Broker    → server.properties + 建 topic
Consumer  → spring.kafka.consumer + spring.kafka.listener
```

# 2、丢消息

## Producer

**什么情况下会丢**：消息还在客户端，**还没可靠写入 Kafka**，应用以为发了或 Broker 其实没落盘。

| 情况 | 说明 |
|------|------|
| **acks=0** | 发出去不等确认，网络失败或 Broker 挂了，客户端不知道 |
| **acks=1** | Leader 应答后、Follower 还没同步，Leader 宕机，消息可能丢 |
| **无重试 / 重试耗尽** | 网络抖动、Broker 短暂不可用，超过 retries 或 delivery.timeout 后放弃 |
| **异步发送不处理失败** | callback 里只打日志，没有补偿或告警，等于静默丢 |
| **进程崩溃** | 消息在缓冲区里，还没 send 完，进程就挂了 |

**配置位置**：`application.yml` → `spring.kafka.producer`，或原生 `Properties`

```yml
spring:
  kafka:
    producer:
      acks: all          # 0 可能丢；1 Leader 确认；all ISR 全部确认
      retries: 3
      properties:
        enable.idempotence: true
        max.in.flight.requests.per.connection: 5
        retry.backoff.ms: 1000
        request.timeout.ms: 60000
        delivery.timeout.ms: 120000
        max.block.ms: 20000
```

| 参数 | 作用 |
|------|------|
| **acks** | 0 不等确认；1 Leader 确认；all 等 ISR 全部确认 |
| **retries** | 发送失败重试次数 |
| **enable.idempotence** | 幂等 Producer，重试不产生重复 record；会强制 acks=all |
| **delivery.timeout.ms** | 从 send 到最终成功/失败的总超时（含 retries） |
| **request.timeout.ms** | 单次请求等待 Broker 响应超时 |
| **max.block.ms** | metadata 不可用或缓冲区满时 send 阻塞上限 |

**代码兜底**

```java
// 同步：失败立刻抛异常
kafkaTemplate.send(topic, key, value).get();

// 异步：失败落本地消息表，定时重发
kafkaTemplate.send(topic, key, value).whenComplete((r, ex) -> {
    if (ex != null) outboxService.save(topic, key, value);
});
```

**小结**：`acks=all` + 幂等 + 重试/超时 + 失败可补偿

## Broker

**什么情况下会丢**：消息已进 Kafka，但 **副本不足或 Leader 选举不当**，已确认的数据仍可能没了。

| 情况 | 说明 |
|------|------|
| **replication.factor=1** | 只有一份，Broker 宕机或磁盘坏，分区数据直接丢 |
| **min.insync.replicas 太低** | acks=all 但只要求 1 个副本，Leader 挂且未同步的 Follower 接不上 |
| **unclean.leader.election=true** | Leader 挂了，从落后很多的 Follower 选新 Leader，未同步数据被截掉 |
| **ISR 全挂** | 极端情况下分区不可写；若之前配置不当，恢复后可能丢历史数据 |
| **消息超限被拒** | 单条超过 message.max.bytes，Producer 收到错误，若未重试等于没进 Kafka |

**配置位置**：`config/server.properties`、建 topic 时 `--replication-factor` / `--config`

```properties
default.replication.factor=3
min.insync.replicas=2
unclean.leader.election.enable=false
message.max.bytes=10485760
```

```bash
# 建 topic
kafka-topics.sh --create --topic my-topic \
  --partitions 3 --replication-factor 3 \
  --config min.insync.replicas=2

# 已有 topic 修改
kafka-configs.sh --alter --topic my-topic \
  --add-config min.insync.replicas=2
```

| 参数 | 作用 |
|------|------|
| **replication.factor** | 分区副本数，生产常用 3 |
| **min.insync.replicas** | 配合 acks=all，ISR 至少 N 个副本写入才算成功 |
| **unclean.leader.election.enable** | false：只从 ISR 选 Leader，宁可停写也不丢已确认数据 |
| **message.max.bytes** | Broker 单条消息上限；Producer max.request.size 不能超过它 |

**与 Producer 配合**

```text
acks=all + replication.factor=3 + min.insync.replicas=2
→ 至少 2 个副本写入成功，Producer 才收到 OK
→ ISR 不足时返回 NOT_ENOUGH_REPLICAS，宁可写失败也不静默丢
```

## Consumer

**什么情况下会丢**：消息已在 Kafka 里，但 **offset 提交了业务没做完**，或 **以为消费了实际没处理**。

| 情况 | 说明 |
|------|------|
| **enable-auto-commit=true** | 后台定时提交 offset，业务还在跑进程就挂了，offset 已前进，消息不会再消费 |
| **先 ack 后处理** | 手动 ack 写在业务前面，ack 后处理失败，这条算丢了 |
| **自动提交 + 处理慢** | poll 后很快自动 commit，大批量还没处理完就提交，崩溃后中间一段丢 |
| **异常吞掉仍提交** | catch 异常不抛出、仍然 ack，失败消息不会被重投 |
| **rebalance 时未处理完** | 分区被分给别的 consumer，旧 consumer 未 ack 的消息可能丢失（取决于提交策略） |

**配置位置**：`spring.kafka.consumer` + `spring.kafka.listener`

```yml
spring:
  kafka:
    consumer:
      enable-auto-commit: false
      max-poll-records: 500
      properties:
        max.poll.interval.ms: 300000
        session.timeout.ms: 45000
    listener:
      ack-mode: manual_immediate
```

| 参数 | 作用 |
|------|------|
| **enable-auto-commit** | true 自动提交（易丢）；false 手动 ack（推荐） |
| **ack-mode** | manual_immediate 业务成功后立即提交 offset |
| **max.poll.interval.ms** | 两次 poll 间业务处理上限，超时 rebalance |
| **max.poll.records** | 一次 poll 最多拉取条数 |

**正确顺序**

```java
@KafkaListener(topics = "my-topic")
public void listen(ConsumerRecord<String, String> record, Acknowledgment ack) {
    doBusiness(record.value());  // 先业务
    ack.acknowledge();           // 成功再 ack；失败不 ack → 重投
}
```

| 做法 | 结果 |
|------|------|
| auto-commit=true | 易丢 |
| 先处理后 ack | 不易丢，失败会重复 |
| 处理成功但 ack 前崩溃 | 重复消费 |

# 3、重复消费

## 常见原因

| 场景 | 原因 |
|------|------|
| ack 前进程挂 | offset 未提交，重启再消费 |
| rebalance | 分区转移，可能重复处理 |
| max.poll.interval.ms 超时 | 被踢出组，未 ack 消息重投 |
| Producer 重试未开幂等 | Kafka 内两条 record |
| 人工重放 | 脚本/运维再发一遍 |

Kafka **不会**替业务去重，需应用层 **幂等消费**。

---

## 落地方案

| 方案 | 适用 |
|------|------|
| **DB 唯一键** | 订单、入库（最常用） |
| **Redis setnx** | 高并发短期去重 |
| **消费位点表** | 强审计 |
| **状态机幂等** | 支付、状态流转 |

**DB 唯一键**

```java
@Transactional
public void handle(OrderEvent event) {
    orderMapper.insertIgnore(event.getOrderId(), event.getPayload());
}
```

**Redis 去重**

```java
public void handle(String msgId, String body) {
    Boolean first = redisTemplate.opsForValue()
            .setIfAbsent("kafka:done:" + msgId, "1", Duration.ofDays(7));
    if (Boolean.FALSE.equals(first)) return;
    doBusiness(body);
}
```

msgId 可用业务 id，或 `topic-partition-offset`。

**消费位点表**

```java
if (offsetStore.exists(group, topic, partition, offset)) {
    ack.acknowledge();
    return;
}
doBusiness(record.value());
offsetStore.save(...);
ack.acknowledge();
```

# 4、面试速记

| 防丢 | 配置 |
|------|------|
| Producer | acks=all、enable.idempotence、retries |
| Broker | RF=3、min.insync.replicas=2、unclean.leader.election=false |
| Consumer | enable-auto-commit=false、manual_immediate、先业务后 ack |

| 防重复 | 配置 |
|--------|------|
| Producer | enable.idempotence（防 Kafka 内重复 record） |
| 业务层 | 唯一键 / Redis / 状态机幂等 |

```text
丢消息：Producer acks=all + 幂等；Broker 三副本 + min.insync；Consumer 手动 ack。
重复消费：至少一次不可避免；Producer 幂等 + 业务层去重。
Broker 参数在 server.properties 和建 topic 时配置，不在 Spring yml 里。
```
