# 4、反向代理与负载均衡

## 1、反向代理 vs 正向代理

| | 正向代理 | 反向代理 |
|---|----------|----------|
| 谁配置 | 客户端 | 服务端 |
| 客户端感知 | 知道代理存在 | 不知道后端是谁 |
| 典型 | VPN、科学上网 | Nginx → Spring Boot |
| 作用 | 隐藏客户端 | 隐藏后端、负载均衡、TLS |

```text
正向：客户端 → 代理 → 目标服务器
反向：客户端 → Nginx → 后端集群（客户端只认 Nginx）
```

---

## 2、proxy_pass 基础

```nginx
upstream backend {
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
    server 192.168.1.103:8080;
    keepalive 64;
}

server {
    listen 80;
    server_name api.example.com;

    location /api/ {
        proxy_pass http://backend;
    }
}
```

### URI 转发规则（面试高频）

| location | proxy_pass | 客户端请求 | 转发到后端 |
|----------|--------------|------------|------------|
| `/api/` | `http://backend` | `/api/user/1` | `/api/user/1` |
| `/api/` | `http://backend/` | `/api/user/1` | `/user/1`（去掉 `/api`） |
| `/api` | `http://backend/` | `/api/user/1` | `/user/1` |

**记忆**：`proxy_pass` 带 **URI 路径**（如 `/`）时会替换 location 匹配部分；**只有域名/IP:端口** 则原样转发。

## 3、必配请求头

后端需要知道真实客户端 IP 和原始协议：

```nginx
location /api/ {
    proxy_pass http://backend;

    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection        "";
}
```

| 头 | 作用 |
|----|------|
| `Host` | 原始域名，后端虚拟主机 / 路由可能依赖 |
| `X-Real-IP` | 客户端真实 IP |
| `X-Forwarded-For` | 代理链路上的 IP 列表 |
| `X-Forwarded-Proto` | 客户端用的是 http 还是 https |
| `Connection ""` | 配合 upstream keepalive，避免 close |

Spring 获取客户端 IP：`X-Forwarded-For` 第一个 IP，或使用 `ForwardedHeaderFilter`。

## 4、代理超时与缓冲

```nginx
location /api/ {
    proxy_pass http://backend;

    # 与后端建立连接超时
    proxy_connect_timeout 60s;
    # 向后端发送请求超时
    proxy_send_timeout    60s;
    # 等待后端响应超时（接口慢时调大，防 504）
    proxy_read_timeout    60s;

    # 开启响应缓冲（高并发推荐）
    proxy_buffering on;
    proxy_buffers 16 64k;
    proxy_busy_buffers_size 128k;
}
```

| 错误 | 常见原因 |
|------|----------|
| **502 Bad Gateway** | 后端未启动、连接拒绝、upstream 全挂 |
| **504 Gateway Timeout** | `proxy_read_timeout` 太短，后端处理慢 |
| **499** | 客户端主动断开（常见于前端取消请求） |

## 5、upstream 负载均衡

### 5.1 默认策略：轮询（round-robin）

```nginx
upstream backend {
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
    server 192.168.1.103:8080;
}
```

### 5.2 加权轮询

```nginx
upstream backend {
    server 192.168.1.101:8080 weight=3;
    server 192.168.1.102:8080 weight=1;
}
```

### 5.3 IP Hash（会话粘滞）

```nginx
upstream backend {
    ip_hash;
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
}
```

同一客户端 IP 固定到同一后端；后端宕机需重新 hash。

### 5.4 least_conn（最少连接）

```nginx
upstream backend {
    least_conn;
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
}
```

适合请求处理时间差异大的场景。

### 5.5 健康检查相关参数

```nginx
upstream backend {
    server 192.168.1.101:8080 max_fails=3 fail_timeout=30s;
    server 192.168.1.102:8080 max_fails=3 fail_timeout=30s backup;
}
```

| 参数 | 说明 |
|------|------|
| `max_fails` | 连续失败次数达到则标记不可用 |
| `fail_timeout` | 不可用持续时间，过后再试 |
| `backup` | 仅当其他 server 都不可用时启用 |
| `down` | 永久下线维护 |

> 开源版 Nginx **无主动 HTTP 健康检查**，仅被动失败检测；需主动探测可用 Nginx Plus 或 OpenResty/lua。

### 5.6 upstream keepalive

```nginx
upstream backend {
    server 127.0.0.1:8080;
    keepalive 32;   # 与每个后端保持的空闲长连接数
}

location /api/ {
    proxy_pass http://backend;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
}
```

减少 Nginx 与后端频繁 TCP 握手，**高并发必开**。

## 6、负载策略对比

| 策略 | 指令 | 适用 |
|------|------|------|
| 轮询 | 默认 | 后端同质、无状态 |
| 加权轮询 | `weight=` | 机器配置不同 |
| IP Hash | `ip_hash` | 简单会话粘滞（无 Redis Session 时） |
| 最少连接 | `least_conn` | 长连接、耗时差异大 |
| 一致性 Hash | `hash $request_uri consistent` | 缓存节点、相同 URI 固定后端 |

## 7、WebSocket 代理

```nginx
location /ws/ {
    proxy_pass http://backend;
    proxy_http_version 1.1;
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host       $host;
    proxy_read_timeout 3600s;   # WebSocket 长连接，超时调大
}
```

## 8、完整生产示例

```nginx
upstream backend {
    server 192.168.1.101:8080 max_fails=3 fail_timeout=30s;
    server 192.168.1.102:8080 max_fails=3 fail_timeout=30s;
    server 192.168.1.103:8080 max_fails=3 fail_timeout=30s;
    keepalive 64;
}

server {
    listen 80;
    server_name example.com;

    location /api/ {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection        "";

        proxy_connect_timeout 60s;
        proxy_send_timeout    60s;
        proxy_read_timeout    60s;

        proxy_buffering on;
        proxy_buffers 16 64k;
    }
}
```
