# 6、性能优化与常见问题

## 1、性能调优要点

### 1.1 Worker 与连接数

| 参数 | 建议 | 说明 |
|------|------|------|
| `worker_processes` | `auto` 或 CPU 核数 | 每核一个 Worker 常见 |
| `worker_connections` | 1024～16384 | 过高占内存 |
| `worker_rlimit_nofile` | 65535 | 须 ≥ worker_connections |
| 理论最大连接 | `worker_processes × worker_connections` | 8×10240 ≈ 8 万 |

Nginx 内存通常 **512MB～2GB** 足够；瓶颈多在连接数、磁盘 IO、后端响应，不在堆内存。

### 1.2 系统参数（与 Nginx 配合）

```bash
# /etc/security/limits.conf
nginx soft nofile 65535
nginx hard nofile 65535

# /etc/sysctl.conf
net.core.somaxconn = 65535
net.ipv4.tcp_tw_reuse = 1
```

改完 `sysctl -p`；systemd 服务加 `LimitNOFILE=65536`。

### 1.3 静态与传输

| 优化 | 指令 | 作用 |
|------|------|------|
| 零拷贝 | `sendfile on` | 静态文件少拷贝 |
| 长连接 | `keepalive_timeout 65` | 减少 TCP 握手 |
| 压缩 | `gzip on` | 文本响应省带宽 |
| 上游长连接 | `upstream { keepalive N }` | Nginx↔后端少握手 |

### 1.4 缓存（反向代理）

```nginx
proxy_cache_path /data/nginx/cache levels=1:2 keys_zone=api_cache:10m max_size=1g inactive=60m;

location /api/ {
    proxy_pass http://backend;
    proxy_cache api_cache;
    proxy_cache_valid 200 10m;
    proxy_cache_key $host$request_uri;
    add_header X-Cache-Status $upstream_cache_status;
}
```

| `$upstream_cache_status` | 含义 |
|---------------------------|------|
| HIT | 命中缓存 |
| MISS | 未命中 |
| BYPASS | 跳过缓存 |

适合读多写少、允许短暂 stale 的接口；**写操作勿缓存**。

## 2、限流与防刷

### 2.1 limit_req（漏桶）

```nginx
# http 块内定义
limit_req_zone $binary_remote_addr zone=req_limit:10m rate=10r/s;

server {
    location /api/ {
        limit_req zone=req_limit burst=20 nodelay;
        proxy_pass http://backend;
    }
}
```

| 参数 | 说明 |
|------|------|
| `rate=10r/s` | 平均每秒 10 请求 |
| `burst=20` | 允许突发 20 个排队 |
| `nodelay` | 突发立即处理，不延迟 |

### 2.2 limit_conn（连接数限制）

```nginx
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;

location / {
    limit_conn conn_limit 10;
}
```

## 3、监控 stub_status

编译时需 `--with-http_stub_status_module`：

```nginx
location /nginx_status {
    stub_status on;
    allow 127.0.0.1;
    deny all;
}
```

```bash
curl http://127.0.0.1/nginx_status
```

输出含：`Active connections`、`accepts`、`handled`、`requests`、Reading/Writing/Waiting。

## 4、日志

### 4.1 访问日志格式

```nginx
log_format main '$remote_addr - [$time_local] "$request" '
                '$status $body_bytes_sent '
                'rt=$request_time uaddr=$upstream_addr urt=$upstream_response_time';
access_log logs/access.log main;
```

| 字段 | 含义 |
|------|------|
| `$request_time` | 请求总耗时 |
| `$upstream_response_time` | 后端响应耗时 |
| `$upstream_addr` | 实际转发后端 |

### 4.2 日志轮转

```bash
vi /etc/logrotate.d/nginx
```

```text
/data/nginx/current/logs/*.log {
    daily
    rotate 14
    missingok
    notifempty
    compress
    sharedscripts
    postrotate
        /opt/nginx/current/sbin/nginx -s reopen
    endscript
}
```

## 5、常见问题排查

| 现象 | 可能原因 | 排查 |
|------|----------|------|
| **502** | 后端未启动、端口错、upstream 全挂 | `curl 后端IP:端口`；看 error.log |
| **504** | 后端慢、`proxy_read_timeout` 太短 | 调大 timeout；查后端慢 SQL |
| **413** | 上传超 `client_max_body_size` | 调大该参数并 reload |
| **404** | root/alias 路径错、SPA 未 try_files | `nginx -T` 看最终配置 |
| **403** | 权限不足、目录无 index | `chown nginx`；检查 SELinux |
| **重定向循环** | http/https 跳转配错 | 检查 `X-Forwarded-Proto` |
| **改配置不生效** | 未 reload、改错文件 | `nginx -t`；确认 `-p` 前缀目录 |

**常用命令**

```bash
nginx -t
nginx -T | less
tail -f /data/nginx/current/logs/error.log
curl -v http://127.0.0.1/api/health
ss -lntp | grep nginx
```

## 6、面试高频

### 6.1 Nginx 为什么高并发？

- **事件驱动 + 异步非阻塞**（epoll），单 Worker 可处理大量连接
- **Master-Worker** 多进程，互不影响
- 静态资源 **sendfile 零拷贝**
- 内存占用小，无 per-request 线程

### 6.2 反向代理原理？

客户端连 Nginx → Nginx 作为客户端连后端 → 双向转发数据；对客户端隐藏后端地址与数量。

### 6.3 负载均衡策略有哪些？

轮询、加权轮询、IP Hash、least_conn、hash（一致性 Hash）。开源版仅被动健康检查。

### 6.4 location 匹配优先级？

`=` 精确 > `^~` 前缀 > 正则 `~` / `~*` > 普通前缀；最长前缀优先。

### 6.5 proxy_pass 末尾带 `/` 的区别？

带 URI 会替换 location 匹配部分；仅 host:port 则原样转发 URI（见第 4 篇表格）。

### 6.6 reload 会影响正在处理的请求吗？

不会粗暴断开。Master 启新 Worker 加载新配置，旧 Worker **处理完当前连接后退出**，属于平滑重载。

### 6.7 Nginx 和 Gateway 怎么分工？

Nginx：边缘 TLS、静态资源、四层/七层反向代理、负载均衡。Gateway：业务路由、鉴权、限流、与注册中心集成。常见 **Nginx → Gateway → 微服务**。

### 6.8 如何获取客户端真实 IP？

`proxy_set_header X-Real-IP $remote_addr;` 和 `X-Forwarded-For $proxy_add_x_forwarded_for;`，后端读这两个头（注意伪造，仅信任内网 Nginx）。

### 6.9 502 和 504 区别？

502：Nginx 作为网关，**拿不到合法后端响应**（连接失败、后端崩溃）。504：连接建立了，**等响应超时**。

### 6.10 为什么生产建议 server_tokens off？

隐藏 `Server: nginx/x.x.x` 版本，减少针对性攻击面。
